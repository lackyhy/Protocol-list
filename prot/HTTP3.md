**HTTP/3** — третья основная версия протокола HTTP, работающая поверх транспортного протокола **QUIC** вместо TCP. Семантика HTTP не изменилась, но благодаря QUIC соединение устанавливается быстрее, потеря пакета в одном потоке не тормозит остальные, а соединение переживает смену сети (например, переход с Wi-Fi на мобильный интернет).

## **Основные характеристики**

| Параметр                    | Описание                                                                 |
| --------------------------- | ------------------------------------------------------------------------ |
| **Уровень OSI**             | Прикладной (Application Layer)                                           |
| **Транспорт**               | QUIC (поверх UDP)                                                        |
| **Порт**                    | UDP 443                                                                  |
| **Стандарт**                | RFC 9114 (2022)                                                          |
| **Сжатие заголовков**       | QPACK (RFC 9204)                                                         |
| **Шифрование**              | Обязательно, TLS 1.3 встроен в QUIC                                      |
| **Идентификатор ALPN**      | `h3`                                                                     |
| **Обнаружение**             | Заголовок `Alt-Svc` или DNS-запись HTTPS (SVCB)                          |

## **Стек протоколов**

```
     HTTP/1.1, HTTP/2          HTTP/3
    +-----------------+    +-----------------+
    |      HTTP       |    |     HTTP/3      |
    +-----------------+    +-----------------+
    |       TLS       |    |  QUIC (+TLS 1.3)|
    +-----------------+    +-----------------+
    |       TCP       |    |       UDP       |
    +-----------------+    +-----------------+
    |       IP        |    |       IP        |
    +-----------------+    +-----------------+
```

## **Преимущества HTTP/3**

| Преимущество                  | Описание                                                     |
| ----------------------------- | ------------------------------------------------------------ |
| **Быстрое соединение**        | 1 RTT для нового, 0-RTT для повторного (TCP+TLS 1.3 — 2 RTT) |
| **Нет HOL blocking**          | Потеря пакета задерживает только свой поток                  |
| **Миграция соединения**       | Connection ID не зависит от IP и порта — смена сети без разрыва |
| **Улучшенный контроль перегрузки** | Реализован в user space, быстрее развивается              |
| **Шифрование заголовков транспорта** | Меньше видно посредникам, меньше «окостенения»       |

## **Head-of-line blocking: HTTP/2 vs HTTP/3**

```
HTTP/2 поверх TCP:
Поток A: [A1][A2][A3]
Поток B: [B1][B2][B3]       Потерян пакет с A2 →
TCP:     A1 B1 [A2 X] B2 A3 B3   все потоки ждут повтора A2

HTTP/3 поверх QUIC:
Поток A: A1 [A2 X] ... ждёт повтора
Поток B: B1 B2 B3 → доставлены сразу
```

## **Потоки в HTTP/3**

HTTP/3 использует потоки QUIC:

| Тип потока                   | Направление      | Назначение                               |
| ---------------------------- | ---------------- | ---------------------------------------- |
| **Request stream**           | Двунаправленный  | Один запрос и ответ                      |
| **Control stream**           | Однонаправленный | SETTINGS, GOAWAY (по одному от каждой стороны) |
| **QPACK encoder stream**     | Однонаправленный | Обновления динамической таблицы          |
| **QPACK decoder stream**     | Однонаправленный | Подтверждения декодера                   |
| **Push stream**              | Однонаправленный | Server Push                              |

## **Типы фреймов HTTP/3**

| Код  | Фрейм            | Описание                                  |
| ---- | ---------------- | ----------------------------------------- |
| 0x00 | **DATA**         | Тело сообщения                            |
| 0x01 | **HEADERS**      | Заголовки (QPACK)                         |
| 0x03 | **CANCEL_PUSH**  | Отмена push                               |
| 0x04 | **SETTINGS**     | Параметры соединения                      |
| 0x05 | **PUSH_PROMISE** | Обещание push                             |
| 0x07 | **GOAWAY**       | Закрытие соединения                       |
| 0x0d | **MAX_PUSH_ID**  | Ограничение push                          |

По сравнению с HTTP/2 исчезли фреймы PING, WINDOW_UPDATE, RST_STREAM, PRIORITY — эти функции выполняет QUIC.

## **QPACK**

QPACK — адаптация HPACK для QUIC. В HPACK динамическая таблица требует строгого порядка доставки, что вернуло бы HOL blocking. QPACK обновляет таблицу через отдельные потоки и позволяет декодировать заголовки без ожидания других потоков.

## **Как браузер узнаёт о поддержке HTTP/3**

### **1. Заголовок Alt-Svc**

Первый запрос идёт по HTTP/2 через TCP, сервер сообщает:

```
alt-svc: h3=":443"; ma=86400
```

Следующие запросы браузер отправляет по HTTP/3.

### **2. DNS-запись HTTPS (SVCB)**

```
example.com. 300 IN HTTPS 1 . alpn="h3,h2" ipv4hint=93.184.216.34
```

Браузер узнаёт о HTTP/3 ещё до первого соединения.

### **3. Fallback**

Если UDP 443 заблокирован, браузер использует HTTP/2 по TCP. Часто запускаются оба соединения параллельно (happy eyeballs).

## **Примеры использования**

### **curl**

```bash
# curl должен быть собран с поддержкой HTTP/3 (ngtcp2/quiche)
curl --http3 -I https://cloudflare.com
curl --http3-only https://www.google.com -o /dev/null -w '%{http_version}\n'
```

### **Nginx (1.25+)**

```nginx
server {
    listen 443 quic reuseport;
    listen 443 ssl;
    http2 on;

    ssl_certificate     /etc/ssl/example.crt;
    ssl_certificate_key /etc/ssl/example.key;
    ssl_protocols TLSv1.3;

    add_header Alt-Svc 'h3=":443"; ma=86400';
}
```

Не забыть открыть **UDP 443** на файрволе.

### **Caddy**

HTTP/3 включён по умолчанию.

### **Проверка в браузере**

- Chrome DevTools → Network → столбец Protocol → `h3`
- `chrome://net-internals/#quic`
- Онлайн: http3check.net

### **Wireshark**

```
quic
http3
```

Для расшифровки нужен `SSLKEYLOGFILE`.

## **Ограничения и проблемы**

1. **Блокировка UDP** — корпоративные сети и некоторые провайдеры блокируют или ограничивают UDP 443
2. **Нагрузка на CPU** — обработка в user space и шифрование каждого пакета дороже, чем TCP в ядре
3. **Middleboxes** — файрволы и DPI не умеют анализировать QUIC
4. **0-RTT** — уязвим к replay-атакам, подходит только для идемпотентных запросов
5. **Отладка** — шифрование транспорта затрудняет диагностику

## **Сравнение HTTP/2 и HTTP/3**

| Характеристика         | HTTP/2               | HTTP/3                    |
| ---------------------- | -------------------- | ------------------------- |
| **Транспорт**          | TCP                  | QUIC (UDP)                |
| **Новое соединение**   | 2–3 RTT (TCP + TLS)  | 1 RTT                     |
| **Повторное соединение** | 1–2 RTT            | 0 RTT                     |
| **HOL blocking**       | На уровне TCP        | Нет                       |
| **Сжатие заголовков**  | HPACK                | QPACK                     |
| **Смена сети**         | Разрыв соединения    | Миграция соединения       |
| **Шифрование**         | TLS 1.2+             | Только TLS 1.3            |
| **Flow control, пинги** | В HTTP/2            | В QUIC                    |
