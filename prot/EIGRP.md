**EIGRP** (Enhanced Interior Gateway Routing Protocol) — протокол внутренней маршрутизации, разработанный Cisco как улучшенная версия IGRP. Его называют «продвинутым дистанционно-векторным» (или гибридным): маршрутизаторы обмениваются векторами расстояний, но, как в link-state протоколах, держат таблицу топологии, отправляют только изменения и сходятся очень быстро благодаря алгоритму DUAL.

## **Основные характеристики**

| Параметр                    | Описание                                                                 |
| --------------------------- | ------------------------------------------------------------------------ |
| **Уровень OSI**             | Сетевой (Network Layer)                                                  |
| **Инкапсуляция**            | IP, номер протокола 88                                                   |
| **Multicast-адрес**         | `224.0.0.10` (IPv4), `ff02::a` (IPv6)                                    |
| **Тип протокола**           | Advanced Distance Vector (гибридный)                                     |
| **Алгоритм**                | DUAL (Diffusing Update Algorithm)                                        |
| **Стандарт**                | Проприетарный Cisco, частично открыт в RFC 7868 (информационный)         |
| **Административная дистанция** | 90 (внутренние), 170 (внешние), 5 (summary)                           |
| **Максимум хопов**          | 100 по умолчанию, до 255                                                 |
| **Надёжность**              | RTP (Reliable Transport Protocol, не путать с RTP для медиа)             |

## **Таблицы EIGRP**

| Таблица                | Описание                                                   |
| ---------------------- | ---------------------------------------------------------- |
| **Neighbor Table**     | Соседи, с которыми установлено соседство                   |
| **Topology Table**     | Все известные пути ко всем сетям от всех соседей           |
| **Routing Table**      | Лучшие пути (Successor) из таблицы топологии               |

## **Типы пакетов**

| Пакет            | Надёжный | Описание                                            |
| ---------------- | -------- | --------------------------------------------------- |
| **Hello**        | Нет      | Обнаружение и поддержание соседства                 |
| **Update**       | Да       | Информация о маршрутах (только изменения)           |
| **Query**        | Да       | Запрос альтернативного пути при потере маршрута     |
| **Reply**        | Да       | Ответ на Query                                      |
| **ACK**          | Нет      | Подтверждение надёжных пакетов (пустой Hello)       |
| **SIA-Query / SIA-Reply** | Да | Проверка зависших запросов                       |

## **Метрика**

Composite-метрика рассчитывается из параметров канала с коэффициентами **K1–K5**:

```
Метрика = 256 × [ K1×BW + (K2×BW)/(256 − Load) + K3×Delay ] × [ K5/(Reliability + K4) ]

По умолчанию K1 = K3 = 1, K2 = K4 = K5 = 0, поэтому:

Метрика = 256 × (BW + Delay)

BW    = 10^7 / минимальная пропускная способность на пути (Кбит/с)
Delay = сумма задержек на пути (в десятках микросекунд)
```

**Wide metrics** (named mode) используют 64-битную метрику и пикосекунды, чтобы различать каналы быстрее 1 Гбит/с.

| Интерфейс     | Пропускная способность | Delay (мкс) |
| ------------- | ---------------------- | ----------- |
| Serial (T1)   | 1 544 Кбит/с           | 20 000      |
| FastEthernet  | 100 000 Кбит/с         | 100         |
| GigabitEthernet | 1 000 000 Кбит/с     | 10          |

## **Алгоритм DUAL**

### **Термины**

| Термин                    | Описание                                                             |
| ------------------------- | -------------------------------------------------------------------- |
| **Feasible Distance (FD)** | Лучшая метрика от этого маршрутизатора до сети                      |
| **Reported Distance (RD)** | Метрика, которую сообщает сосед (от соседа до сети)                 |
| **Successor**             | Сосед с лучшим путём — используется для маршрутизации               |
| **Feasible Successor (FS)** | Резервный путь без петли, готовый к мгновенному переключению      |
| **Feasibility Condition** | Сосед может быть FS, если **RD соседа < FD** текущего маршрута       |

### **Пример**

```
            R2 (RD=10)
          /          \
 R1 ─────              ───── Сеть X
          \          /
            R3 (RD=15)

R1 → X через R2: 20 + 10 = 30  → Successor, FD = 30
R1 → X через R3: 25 + 15 = 40  → RD (15) < FD (30) → Feasible Successor
```

Если связь с R2 упадёт, R1 **мгновенно** переключится на R3 без пересчёта. Если FS нет, маршрут переходит в состояние **Active**, и маршрутизатор рассылает Query соседям.

### **Stuck In Active (SIA)**

Если ответ на Query не пришёл за 3 минуты, соседство сбрасывается. Решения: суммирование маршрутов и **stub**-маршрутизаторы, чтобы ограничить область распространения Query.

## **Установление соседства**

Условия:
1. Совпадает номер **автономной системы** (AS)
2. Совпадают **K-значения**
3. Интерфейсы в одной подсети
4. Совпадает аутентификация

### **Таймеры**

| Канал                     | Hello  | Hold   |
| ------------------------- | ------ | ------ |
| LAN, высокоскоростные     | 5 с    | 15 с   |
| Медленные NBMA (≤ T1)     | 60 с   | 180 с  |

## **Примеры конфигурации**

### **Classic mode (Cisco IOS)**

```
router eigrp 100
 network 10.0.0.0 0.255.255.255
 network 192.168.1.0 0.0.0.255
 passive-interface GigabitEthernet0/2
 no auto-summary
 eigrp stub connected summary
```

### **Named mode (рекомендуется)**

```
router eigrp CORP
 address-family ipv4 unicast autonomous-system 100
  network 10.0.0.0 0.255.255.255
  af-interface GigabitEthernet0/0
   authentication mode hmac-sha-256 S3cret
   summary-address 10.1.0.0 255.255.0.0
  exit-af-interface
  topology base
   variance 2
  exit-af-topology
```

### **Балансировка по неравным путям**

```
router eigrp 100
 variance 2       ! использовать FS с метрикой до 2 × FD
```

EIGRP — единственный распространённый IGP, умеющий **балансировку по путям с разной стоимостью**.

### **Проверка**

```
show ip eigrp neighbors
show ip eigrp topology
show ip eigrp topology all-links
show ip route eigrp
show ip protocols
debug eigrp packets
```

### **FRRouting (Linux)**

```
router eigrp 100
 network 10.0.0.0/8
```

FRR поддерживает EIGRP частично (без некоторых функций Cisco).

### **Wireshark**

```
eigrp
ip.proto == 88
```

## **Безопасность EIGRP**

- **Аутентификация** — MD5 (classic) или HMAC-SHA-256 (named mode)
- **Passive interface** на портах к пользователям
- Фильтрация маршрутов (`distribute-list`, route-map)
- Ограничение количества принимаемых маршрутов (`maximum-prefix`)

## **Сравнение EIGRP, OSPF и RIP**

| Характеристика       | EIGRP                | OSPF                  | RIPv2               |
| -------------------- | -------------------- | --------------------- | ------------------- |
| **Тип**              | Advanced DV          | Link-State            | Distance Vector     |
| **Алгоритм**         | DUAL                 | SPF (Дейкстра)        | Беллмана-Форда      |
| **Метрика**          | Пропускная способность + задержка | Стоимость (cost) | Хопы             |
| **Конвергенция**     | Очень быстрая (с FS) | Быстрая               | Медленная           |
| **Неравная балансировка** | Да (variance)   | Нет                   | Нет                 |
| **Обновления**       | Только изменения     | Изменения + обновление раз в 30 минут | Каждые 30 с |
| **Иерархия**         | Нет (суммирование)   | Области               | Нет                 |
| **Вендоры**          | В основном Cisco     | Все                   | Все                 |
| **AD (Cisco)**       | 90                   | 110                   | 120                 |
