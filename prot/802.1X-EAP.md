**IEEE 802.1X** — стандарт контроля доступа к сети на уровне порта (Port-Based Network Access Control). Пока устройство не прошло аутентификацию, порт коммутатора или Wi-Fi соединение пропускает только служебный трафик аутентификации. **EAP** (Extensible Authentication Protocol) — гибкий каркас, внутри которого выполняется сама аутентификация: по сертификатам, паролям, SIM-картам и т.д.

## **Основные характеристики**

| Параметр                    | Описание                                                                 |
| --------------------------- | ------------------------------------------------------------------------ |
| **Уровень OSI**             | Канальный (Data Link Layer)                                              |
| **Стандарты**               | IEEE 802.1X-2020, EAP — RFC 3748                                         |
| **Инкапсуляция**            | EAPOL (EAP over LAN), EtherType `0x888E`                                 |
| **Адрес EAPOL**             | `01:80:C2:00:00:03` (PAE group address)                                  |
| **Сервер аутентификации**   | Обычно RADIUS                                                            |
| **Применение**              | Проводные сети, Wi-Fi Enterprise (WPA2/WPA3-Enterprise), VPN             |

## **Участники 802.1X**

| Роль                         | Описание                                           | Пример                       |
| ---------------------------- | -------------------------------------------------- | ---------------------------- |
| **Supplicant**               | Устройство, которое хочет получить доступ          | Ноутбук, телефон (wpa_supplicant, Windows) |
| **Authenticator**            | Устройство, контролирующее порт                    | Коммутатор, точка доступа    |
| **Authentication Server**    | Принимает решение                                  | RADIUS (FreeRADIUS, NPS, ISE) |

```
Supplicant  <── EAPOL ──>  Authenticator  <── RADIUS ──>  Authentication Server
 (ноутбук)                 (коммутатор)                    (FreeRADIUS)
```

Authenticator не разбирает EAP — он просто перекладывает EAP-пакеты из EAPOL в RADIUS и обратно.

## **Состояние порта**

```
До аутентификации:                    После аутентификации:
  +----------+                          +----------+
  | Порт     |  только EAPOL            | Порт     |  весь трафик
  | Unauthorized | ─────X─── данные    | Authorized | ──────────>
  +----------+                          +----------+
```

## **Типы пакетов EAPOL**

| Тип | Пакет                  | Описание                                   |
| --- | ---------------------- | ------------------------------------------ |
| 0   | **EAP-Packet**         | Содержит EAP-сообщение                     |
| 1   | **EAPOL-Start**        | Клиент инициирует аутентификацию           |
| 2   | **EAPOL-Logoff**       | Клиент завершает сеанс                     |
| 3   | **EAPOL-Key**          | Обмен ключами (4-way handshake в Wi-Fi)    |
| 4   | **EAPOL-Encapsulated-ASF-Alert** | Оповещения                       |
| 5   | **EAPOL-MKA**          | MACsec Key Agreement (802.1AE)             |

## **Структура EAP-пакета**

| Поле           | Размер (байты) | Описание                                      |
| -------------- | -------------- | --------------------------------------------- |
| **Code**       | 1              | 1 = Request, 2 = Response, 3 = Success, 4 = Failure |
| **Identifier** | 1              | Сопоставление запроса и ответа                |
| **Length**     | 2              | Длина                                         |
| **Type**       | 1              | Метод EAP (только для Request/Response)       |
| **Data**       | Переменный     | Данные метода                                 |

| Type | Метод          |

## **Процесс аутентификации**

```
Supplicant              Authenticator               RADIUS
    |                        |                         |
    |--- EAPOL-Start ------->|                         |
    |<-- EAP-Request/Identity|                         |
    |--- EAP-Response/Identity (alice) --------------->|  Access-Request
    |                        |<-- Access-Challenge ----|
    |<-- EAP-Request/PEAP ---|  (Start TLS)            |
    |                        |                         |
    |      ... TLS handshake, внутренний метод (MS-CHAPv2) ...
    |                        |                         |
    |                        |<-- Access-Accept -------|  + VLAN, ключи
    |<-- EAP-Success --------|                         |
    |                        |                         |
    |<== Порт открыт (Wi-Fi: 4-way handshake EAPOL-Key) ==>|
```

## **Методы EAP**

| Метод          | Аутентификация клиента         | Сертификат сервера | Безопасность | Описание                          |
| -------------- | ------------------------------ | ------------------ | ------------ | --------------------------------- |
| **EAP-TLS**    | Сертификат                     | Да                 | Очень высокая | Взаимная аутентификация, эталон  |
| **PEAP (MSCHAPv2)** | Логин и пароль            | Да                 | Средняя      | Самый распространённый в Windows/AD |
| **EAP-TTLS**   | Пароль (PAP, MSCHAPv2 и др.)   | Да                 | Средняя      | Гибкий, популярен в Linux/eduroam |
| **EAP-FAST**   | Пароль + PAC                   | Опционально        | Средняя      | Cisco                             |
| **TEAP**       | Сертификат и/или пароль        | Да                 | Высокая      | Преемник EAP-FAST (RFC 7170)      |
| **EAP-PWD**    | Пароль                         | Нет                | Высокая      | Без сертификатов, устойчив к подбору |
| **EAP-SIM / AKA** | SIM-карта                   | —                  | Высокая      | Wi-Fi операторов связи            |
| **EAP-MD5**    | Пароль                         | Нет                | Низкая       | Устарел, нет защиты               |

## **Дополнительные механизмы**

| Механизм               | Описание                                                       |
| ---------------------- | -------------------------------------------------------------- |
| **MAB**                | MAC Authentication Bypass — для принтеров и IP-телефонов без 802.1X |
| **Guest VLAN**         | VLAN для устройств без supplicant                              |
| **Auth-Fail VLAN**     | VLAN для не прошедших аутентификацию                           |
| **Dynamic VLAN**       | RADIUS назначает VLAN в зависимости от пользователя            |
| **Downloadable ACL**   | RADIUS передаёт ACL для порта                                  |
| **Multi-Auth / Multi-Domain** | Несколько устройств на порту (ПК за IP-телефоном)        |
| **MACsec (802.1AE)**   | Шифрование канала после аутентификации                         |

## **Примеры конфигурации**

### **Cisco IOS (коммутатор)**

```
aaa new-model
aaa authentication dot1x default group radius
aaa authorization network default group radius
dot1x system-auth-control

radius server ISE
 address ipv4 10.0.0.10 auth-port 1812 acct-port 1813
 key Str0ng-Secret

interface GigabitEthernet0/5
 switchport mode access
 switchport access vlan 10
 authentication port-control auto
 authentication host-mode multi-auth
 authentication order dot1x mab
 mab
 dot1x pae authenticator
 dot1x timeout tx-period 10
 spanning-tree portfast
```

```
show authentication sessions
show authentication sessions interface Gi0/5 details
show dot1x all
```

### **Linux (wpa_supplicant, проводная сеть)**

```
# /etc/wpa_supplicant/wired.conf
ctrl_interface=/var/run/wpa_supplicant
ap_scan=0
network={
    key_mgmt=IEEE8021X
    eap=PEAP
    identity="alice"
    password="secret"
    ca_cert="/etc/ssl/certs/corp-ca.pem"
    phase2="auth=MSCHAPV2"
}
```

```bash
wpa_supplicant -D wired -i eth0 -c /etc/wpa_supplicant/wired.conf
```

### **Linux (Wi-Fi, EAP-TLS)**

```
network={
    ssid="CorpWiFi"
    key_mgmt=WPA-EAP
    eap=TLS
    identity="alice@example.com"
    ca_cert="/etc/certs/ca.pem"
    client_cert="/etc/certs/alice.pem"
    private_key="/etc/certs/alice.key"
}
```

## **Безопасность**

### **Атаки**

| Атака                          | Описание                                                    |
| ------------------------------ | ----------------------------------------------------------- |
| **Rogue AP / Evil Twin**       | Поддельная точка доступа собирает хэши MS-CHAPv2, если клиент не проверяет сертификат сервера |
| **Взлом MS-CHAPv2**            | Хэш подбирается или сводится к взлому DES                   |
| **Обход через хаб / bridge**   | Злоумышленник садится между авторизованным ПК и портом      |
| **MAB spoofing**               | Подмена MAC-адреса принтера                                 |
| **Перехват Identity**          | Имя пользователя передаётся до туннеля открыто              |

### **Защита**

- **Обязательная проверка сертификата сервера** и его имени на клиентах (через GPO/MDM)
- EAP-TLS вместо паролей
- Анонимная внешняя идентичность (`anonymous@example.com`)
- MACsec против подключения в разрыв
- MAB только с профилированием и ограниченными ACL

## **Сравнение 802.1X, MAB и Captive Portal**

| Характеристика       | 802.1X                 | MAB                 | Captive Portal (Web Auth) |
| -------------------- | ---------------------- | ------------------- | ------------------------- |
| **Что проверяется**  | Пользователь/устройство | MAC-адрес          | Логин на веб-странице     |
| **Безопасность**     | Высокая                | Низкая              | Средняя                   |
| **Нужен клиент**     | Supplicant (встроен в ОС) | Нет              | Браузер                   |
| **Применение**       | Корпоративные устройства | Принтеры, IoT     | Гости                     |
