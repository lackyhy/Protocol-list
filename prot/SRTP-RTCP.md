**RTCP** (RTP Control Protocol) — протокол-компаньон [RTP](RTP.md), который передаёт статистику о качестве медиапотока (потери, джиттер, задержку) и помогает синхронизировать аудио с видео. **SRTP** (Secure RTP) — защищённая версия RTP: она шифрует медиаданные и проверяет их целостность. Вместе RTP, RTCP и SRTP обеспечивают передачу голоса и видео в VoIP, видеоконференциях и WebRTC.

## **Основные характеристики**

| Протокол  | Расшифровка              | Стандарт            | Назначение                                |
| --------- | ------------------------ | ------------------- | ----------------------------------------- |
| **RTP**   | Real-time Transport Protocol | RFC 3550         | Передача медиаданных                      |
| **RTCP**  | RTP Control Protocol     | RFC 3550            | Контроль качества, синхронизация          |
| **SRTP**  | Secure RTP               | RFC 3711            | Шифрование и аутентификация RTP           |
| **SRTCP** | Secure RTCP              | RFC 3711            | Защита RTCP                               |

## **RTCP**

### **Назначение**

| Функция                | Описание                                                      |
| ---------------------- | ------------------------------------------------------------- |
| **Обратная связь о качестве** | Потери пакетов, джиттер, задержка                      |
| **Синхронизация (lip sync)** | Сопоставление аудио и видео через общие часы            |
| **Идентификация участников** | CNAME — уникальное имя источника                        |
| **Управление частотой** | Отправители подстраивают битрейт по отчётам о потерях        |

### **Порт**

RTCP обычно использует порт на **единицу больше**, чем RTP (RTP — чётный, RTCP — нечётный). В WebRTC применяется **мультиплексирование** RTP и RTCP на одном порту (RFC 5761, `a=rtcp-mux`).

### **Типы пакетов RTCP**

| Тип | Пакет                       | Описание                                         |
| --- | --------------------------- | ------------------------------------------------ |
| 200 | **SR** (Sender Report)      | Статистика от активного отправителя + метки времени для синхронизации |
| 201 | **RR** (Receiver Report)    | Статистика от получателя (потери, джиттер)       |
| 202 | **SDES** (Source Description) | Описание источника (CNAME)                     |
| 203 | **BYE**                     | Участник покидает сессию                          |
| 204 | **APP**                     | Произвольные данные приложения                    |
| 205 | **RTPFB**                   | Transport-layer feedback (NACK, TWCC)            |
| 206 | **PSFB**                    | Payload-specific feedback (PLI, FIR — запрос ключевого кадра) |

### **Содержимое Receiver Report**

| Поле                      | Описание                                        |
| ------------------------- | ----------------------------------------------- |
| **Fraction Lost**         | Доля потерянных пакетов с прошлого отчёта        |
| **Cumulative Lost**       | Всего потеряно за сессию                         |
| **Highest Sequence Number** | Наибольший принятый номер                      |
| **Interarrival Jitter**   | Колебания времени прихода пакетов               |
| **LSR / DLSR**            | Для расчёта RTT                                 |

RTCP ограничивает свой трафик до **~5%** от медиапотока, чтобы не мешать данным.

## **SRTP**

SRTP добавляет к RTP три вещи: **шифрование** полезной нагрузки, **аутентификацию** (защиту целостности) и **защиту от повтора**. Заголовок RTP остаётся незашифрованным (нужен для маршрутизации), шифруется только медиаданные.

### **Структура пакета SRTP**

```
| RTP Header | Зашифрованная полезная нагрузка | [MKI] | Authentication Tag |
  (открыт)     (AES)                                     (HMAC-SHA1, обычно 80 бит)
```

| Элемент                | Описание                                               |
| ---------------------- | ------------------------------------------------------ |
| **Шифрование**         | AES в режиме Counter (AES-CM) или AES-f8; AEAD: AES-GCM |
| **Аутентификация**     | HMAC-SHA1 (тег 32 или 80 бит) или встроенная в GCM     |
| **Защита от повтора**  | Окно по индексу пакетов                                |
| **MKI**                | Master Key Identifier (опционально, для смены ключей)  |

### **Вывод ключей**

Из одного **мастер-ключа** и **мастер-соли** с помощью KDF выводятся отдельные ключи для шифрования, аутентификации и соли. Это защищает от атак при большом объёме трафика.

## **Согласование ключей SRTP**

SRTP сам не передаёт ключи — для этого используются отдельные механизмы:

| Метод            | Описание                                                  | Где используется         |
| ---------------- | --------------------------------------------------------- | ------------------------ |
| **DTLS-SRTP**    | Ключи согласуются по DTLS (RFC 5764)                      | **WebRTC** (обязательно) |
| **SDES**         | Ключи передаются в SDP открытым текстом (должен быть защищён TLS/SIPS) | SIP VoIP        |
| **ZRTP**         | Диффи-Хеллман прямо в медиапотоке + проверка по голосу    | Secure-телефоны (RedPhone, Jitsi) |
| **MIKEY**        | Multimedia Internet KEYing                                | IMS, 3GPP                |

### **DTLS-SRTP (WebRTC)**

```
1. SDP содержит отпечаток DTLS-сертификата (a=fingerprint)
2. Участники выполняют DTLS handshake поверх уже установленного ICE-пути
3. Из DTLS выводятся мастер-ключи SRTP
4. Медиа идёт как SRTP (не внутри DTLS, а рядом)
```

Это защищает от MITM при условии, что отпечаток пришёл по защищённой сигнализации.

## **Профили SRTP**

| Профиль                        | Шифр        | Аутентификация     |
| ------------------------------ | ----------- | ------------------ |
| `SRTP_AES128_CM_HMAC_SHA1_80`  | AES-128-CM  | HMAC-SHA1 80 бит   |
| `SRTP_AES128_CM_HMAC_SHA1_32`  | AES-128-CM  | HMAC-SHA1 32 бита  |
| `SRTP_AEAD_AES_128_GCM`        | AES-128-GCM | AEAD (встроенная)  |
| `SRTP_AEAD_AES_256_GCM`        | AES-256-GCM | AEAD (встроенная)  |

## **Примеры использования**

### **SDP с SRTP (DTLS-SRTP, WebRTC)**

```
m=audio 9 UDP/TLS/RTP/SAVPF 111
a=fingerprint:sha-256 AB:CD:EF:...
a=setup:actpass
a=rtcp-mux
```

### **SDP с SRTP (SDES, SIP)**

```
m=audio 49170 RTP/SAVP 0
a=crypto:1 AES_CM_128_HMAC_SHA1_80 inline:WVNfX19zZW1jdGwgKJK...
```

`RTP/SAVP` = Secure Audio/Video Profile. `inline:` содержит ключ в base64 — поэтому SDP обязан передаваться по защищённому каналу.

### **Захват RTCP-статистики**

```bash
# ffmpeg-приём с RTCP
ffmpeg -protocol_whitelist file,udp,rtp -i stream.sdp out.mp4
```

### **Wireshark**

```
rtcp
rtcp.pt == 200          # Sender Report
srtp
rtcp.ssrc
```

Wireshark умеет строить графики джиттера и потерь: Telephony → RTP → Stream Analysis. Для SRTP содержимое зашифровано, видна только структура.

### **Тест SRTP с помощью libsrtp**

```bash
# из пакета libsrtp2 / srtp-tools
rtpw -s -k <ключ_base64> -a -e 128 203.0.113.5 5004   # отправитель
rtpw -r -k <ключ_base64> -a -e 128 0.0.0.0 5004       # получатель
```

## **Безопасность**

### **Что защищает SRTP**

- **Конфиденциальность** — медиаданные зашифрованы
- **Целостность** — изменение пакетов обнаруживается (HMAC/GCM)
- **Защита от повтора** — старые пакеты отбрасываются

### **Чего SRTP не делает сам**

- **Не согласует ключи** — это задача DTLS-SRTP / SDES / ZRTP
- **Не скрывает заголовок RTP** — видны SSRC, тип нагрузки, метки времени
- **Не защищает метаданные** сессии (кто с кем) — это уровень сигнализации

### **Риски**

| Риск                          | Описание / защита                                     |
| ----------------------------- | ----------------------------------------------------- |
| **SDES без TLS**              | Ключ в SDP виден всем → всегда SIPS/TLS               |
| **Слабая аутентификация (32 бита)** | Легче подделать → предпочтительно 80 бит или GCM |
| **Незащищённая сигнализация** | MITM может подменить отпечаток DTLS → WSS/HTTPS/SIPS  |
| **Нешифрованный RTP**         | VoIP без SRTP прослушивается (Wireshark восстанавливает аудио) |

## **Сравнение RTP, SRTP и RTCP**

| Характеристика    | RTP                 | SRTP                     | RTCP                     |
| ----------------- | ------------------- | ------------------------ | ------------------------ |
| **Что передаёт**  | Медиаданные         | Зашифрованные медиаданные | Статистику и управление |
| **Шифрование**    | Нет                 | Да                       | SRTCP — да               |
| **Объём трафика** | Основной поток      | Основной поток           | ~5% от медиа             |
| **Профиль SDP**   | `RTP/AVP`           | `RTP/SAVP`, `UDP/TLS/RTP/SAVPF` | тот же, что у RTP |
| **Обязателен в WebRTC** | —             | Да                       | Да                       |
