**NDP** (Neighbor Discovery Protocol) — протокол обнаружения соседей в IPv6. Он объединяет функции нескольких протоколов IPv4: ARP (поиск MAC-адреса по IP), ICMP Router Discovery (поиск шлюза) и ICMP Redirect. NDP работает поверх ICMPv6 и использует multicast вместо broadcast.

## **Основные характеристики**

| Параметр                    | Описание                                                                 |
| --------------------------- | ------------------------------------------------------------------------ |
| **Уровень OSI**             | Сетевой / канальный (работает на стыке)                                  |
| **Стандарт**                | RFC 4861, RFC 4862 (SLAAC)                                               |
| **Инкапсуляция**            | ICMPv6 (типы 133–137)                                                    |
| **Hop Limit**               | Всегда 255 (защита от пакетов из других сетей)                           |
| **Замещает**                | ARP, ICMP Router Discovery, ICMP Redirect                                |
| **Защищённая версия**       | SEND (Secure Neighbor Discovery, RFC 3971)                               |

## **Сообщения NDP**

| Type | Сообщение                    | Отправитель → Получатель                       | Назначение                              |
| ---- | ---------------------------- | ---------------------------------------------- | --------------------------------------- |
| 133  | Router Solicitation (RS)     | Хост → `ff02::2` (все роутеры)                 | Запрос параметров сети                  |
| 134  | Router Advertisement (RA)    | Роутер → `ff02::1` (все узлы) или хосту        | Префикс, шлюз, MTU, флаги DHCPv6        |
| 135  | Neighbor Solicitation (NS)   | Узел → Solicited-Node multicast                | Запрос MAC-адреса, DAD, проверка доступности |
| 136  | Neighbor Advertisement (NA)  | Узел → запросившему / `ff02::1`                | Ответ с MAC-адресом                     |
| 137  | Redirect                     | Роутер → хост                                  | «Для этого адреса есть шлюз лучше»      |

## **Функции NDP**

| Функция                              | Сообщения   | Аналог в IPv4        |
| ------------------------------------ | ----------- | -------------------- |
| **Разрешение адресов**               | NS / NA     | ARP                  |
| **Обнаружение маршрутизаторов**      | RS / RA     | ICMP Router Discovery |
| **Обнаружение префиксов**            | RA          | DHCP                 |
| **Автоконфигурация адресов (SLAAC)** | RA          | DHCP                 |
| **Обнаружение дубликатов (DAD)**     | NS / NA     | Gratuitous ARP       |
| **Проверка доступности соседа (NUD)** | NS / NA    | —                    |
| **Перенаправление**                  | Redirect    | ICMP Redirect        |

## **Разрешение адресов (Address Resolution)**

### **Solicited-Node Multicast**

Вместо широковещательной рассылки NS отправляется на специальный multicast-адрес, который зависит от IP цели. Его слушает только нужный узел (и редкие совпадения).

```
Формат:  ff02::1:ff + последние 24 бита IPv6-адреса

IPv6:            2001:db8::1a2b:3c4d
Solicited-Node:  ff02::1:ff2b:3c4d
MAC multicast:   33:33:ff:2b:3c:4d
```

### **Процесс**

```
Узел A (2001:db8::10)                         Узел B (2001:db8::20)
       |                                              |
       |-- NS: "Кто 2001:db8::20?" ------------------>|
       |   Dst: ff02::1:ff00:20                       |
       |   Опция: MAC A                               |
       |                                              |
       |<-- NA: "2001:db8::20 — это 00:11:22:33:44:55"|
       |   Dst: 2001:db8::10 (unicast)                |
       |   Флаги: S=1 (Solicited), O=1 (Override)     |
       |                                              |
  Запись в Neighbor Cache                             |
```

## **Neighbor Cache (кэш соседей)**

Аналог ARP-таблицы. Каждая запись имеет состояние:

| Состояние      | Описание                                                        |
| -------------- | --------------------------------------------------------------- |
| **INCOMPLETE** | NS отправлен, ответа ещё нет                                    |
| **REACHABLE**  | Сосед подтверждён недавно (по умолчанию ~30 секунд)             |
| **STALE**      | Время подтверждения истекло, но запись пригодна                 |
| **DELAY**      | Пакет отправлен по STALE-записи, ждём подтверждения от TCP и т.п. |
| **PROBE**      | Отправляются unicast NS для проверки доступности                |
| **FAILED**     | Сосед не ответил                                                |
| **PERMANENT**  | Статическая запись                                              |

## **Router Advertisement**

### **Содержимое RA**

| Поле / опция              | Описание                                                       |
| ------------------------- | -------------------------------------------------------------- |
| **Cur Hop Limit**         | Рекомендуемый Hop Limit для хостов                             |
| **Флаг M (Managed)**      | Адрес получать через DHCPv6 (stateful)                         |
| **Флаг O (Other)**        | Прочие параметры (DNS) получать через DHCPv6                   |
| **Router Lifetime**       | Сколько секунд роутер можно использовать как шлюз (0 = не шлюз) |
| **Reachable Time**        | Время жизни REACHABLE-записей                                  |
| **Prefix Information**    | Префикс, флаги **L** (on-link) и **A** (для SLAAC), время жизни |
| **MTU**                   | MTU канала                                                     |
| **Source Link-Layer Address** | MAC маршрутизатора                                         |
| **RDNSS / DNSSL**         | DNS-серверы и домены поиска (RFC 8106)                         |

### **Комбинации флагов M/O**

| M | O | Режим                                                  |
| - | - | ------------------------------------------------------ |
| 0 | 0 | Только SLAAC, DNS через RDNSS                          |
| 0 | 1 | SLAAC + Stateless DHCPv6 (только DNS и опции)          |
| 1 | — | Stateful DHCPv6 (адрес выдаёт сервер)                  |

## **DAD (Duplicate Address Detection)**

Перед использованием любого unicast-адреса узел проверяет, не занят ли он:

```
1. Адрес помечается как "tentative" (пробный)
2. Узел отправляет NS:
   Src: ::  (unspecified)
   Dst: Solicited-Node адрес проверяемого IP
   Target: проверяемый адрес
3. Если пришёл NA — адрес занят, использовать нельзя
4. Если ответа нет (~1 секунда) — адрес назначается
```

## **Примеры использования**

### **Просмотр кэша соседей**

```bash
# Linux
ip -6 neigh show

# Windows
netsh interface ipv6 show neighbors
Get-NetNeighbor -AddressFamily IPv6

# macOS
ndp -an
```

### **Управление кэшем (Linux)**

```bash
# Добавить статическую запись
ip -6 neigh add 2001:db8::20 lladdr 00:11:22:33:44:55 dev eth0

# Очистить кэш
ip -6 neigh flush dev eth0
```

### **Отправка RS вручную**

```bash
rdisc6 eth0        # из пакета ndisc6
ndisc6 2001:db8::1 eth0
```

### **Раздача RA на Linux (radvd)**

```
# /etc/radvd.conf
interface eth0 {
    AdvSendAdvert on;
    MinRtrAdvInterval 30;
    MaxRtrAdvInterval 100;
    prefix 2001:db8:1::/64 {
        AdvOnLink on;
        AdvAutonomous on;
    };
    RDNSS 2001:db8:1::53 { };
};
```

### **Cisco IOS**

```
interface GigabitEthernet0/1
 ipv6 address 2001:db8:1::1/64
 ipv6 nd prefix 2001:db8:1::/64
 ipv6 nd other-config-flag
 ipv6 nd ra interval 200
```

### **Wireshark**

```
icmpv6.type >= 133 && icmpv6.type <= 137
```

## **Безопасность NDP**

### **Угрозы**

| Атака                        | Описание                                                 |
| ---------------------------- | -------------------------------------------------------- |
| **NA Spoofing**              | Подделка ответа с MAC атакующего (MITM)                  |
| **Rogue RA**                 | Поддельный роутер становится шлюзом по умолчанию         |
| **RA с Router Lifetime = 0** | Удаление легитимного шлюза у хостов                      |
| **DAD DoS**                  | Ответ на каждую проверку DAD — узлы не получают адреса   |
| **NDP Cache Exhaustion**     | Сканирование /64 подсети переполняет кэш роутера         |
| **Redirect**                 | Перенаправление трафика через атакующего                 |

### **Защита**

- **RA Guard** — коммутатор пропускает RA только с портов маршрутизаторов
- **ND Inspection / IPv6 Snooping** — проверка NS/NA по таблице привязок
- **SEND** — подпись сообщений NDP (CGA-адреса), практически не используется
- Ограничение количества записей в кэше и rate limiting на роутере
- Мониторинг: `ndpmon`, `ramond`

## **Сравнение с ARP**

| Характеристика        | ARP (IPv4)                     | NDP (IPv6)                         |
| --------------------- | ------------------------------ | ---------------------------------- |
| **Уровень**           | Канальный (EtherType 0x0806)   | Сетевой (ICMPv6)                   |
| **Рассылка запроса**  | Broadcast                      | Solicited-Node multicast           |
| **Поиск шлюза**       | Нет (через DHCP)               | Да (RS/RA)                         |
| **Проверка дубликатов** | Gratuitous ARP (необязательно) | DAD (обязательно)                |
| **Проверка доступности** | Нет                         | NUD                                |
| **Защита**            | Нет (Dynamic ARP Inspection)   | SEND, RA Guard                     |
