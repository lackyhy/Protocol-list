**GRE** (Generic Routing Encapsulation) — простой протокол туннелирования, разработанный Cisco. Он упаковывает пакеты почти любого протокола сетевого уровня (IPv4, IPv6, multicast, даже Ethernet-кадры) внутрь IP-пакетов. GRE не шифрует данные, но позволяет передавать через туннель multicast и протоколы маршрутизации (OSPF, EIGRP), поэтому часто используется вместе с IPsec.

## **Основные характеристики**

| Параметр                    | Описание                                                                 |
| --------------------------- | ------------------------------------------------------------------------ |
| **Уровень OSI**             | Сетевой (туннелирование L3 в L3)                                         |
| **Инкапсуляция**            | IP, номер протокола 47                                                   |
| **Стандарты**               | RFC 2784, RFC 2890 (Key и Sequence Number)                               |
| **Накладные расходы**       | 24 байта (20 — внешний IP + 4 — GRE), больше с опциями                   |
| **Шифрование**              | Нет                                                                      |
| **Аутентификация**          | Нет                                                                      |
| **Состояние**               | Stateless — туннель «поднят», даже если другая сторона недоступна (без keepalive) |
| **Порты**                   | Нет (протокол IP, не TCP/UDP)                                            |

## **Структура пакета**

```
| Внешний IP-заголовок (proto 47) | GRE-заголовок | Исходный пакет (IP, IPv6, Ethernet...) |
         20 байт                    4–16 байт
```

### **GRE-заголовок**

| Поле                   | Размер (биты) | Описание                                         |
| ---------------------- | ------------- | ------------------------------------------------ |
| **C (Checksum Present)** | 1           | Есть ли контрольная сумма                        |
| **K (Key Present)**    | 1             | Есть ли поле Key                                 |
| **S (Sequence Present)** | 1           | Есть ли номер последовательности                 |
| **Reserved0**          | 9             | Зарезервировано                                  |
| **Version**            | 3             | 0 (1 — Enhanced GRE для PPTP)                    |
| **Protocol Type**      | 16            | EtherType вложенного протокола                   |
| **Checksum + Reserved1** | 32 (опц.)   | Контрольная сумма                                |
| **Key**                | 32 (опц.)     | Идентификатор туннеля (различение туннелей)      |
| **Sequence Number**    | 32 (опц.)     | Порядковый номер                                 |

### **Protocol Type**

| Значение  | Вложенный протокол              |
| --------- | ------------------------------- |
| `0x0800`  | IPv4                            |
| `0x86DD`  | IPv6                            |
| `0x6558`  | Transparent Ethernet Bridging (GRETAP — L2 поверх GRE) |
| `0x8847`  | MPLS                            |
| `0x880B`  | PPP (Enhanced GRE, PPTP)        |

## **Как работает GRE**

```
Офис A (192.168.1.0/24)                              Офис B (192.168.2.0/24)
  [Router A] 203.0.113.1  ======== интернет ======== 198.51.100.1 [Router B]
   Tunnel0: 10.0.0.1/30                                Tunnel0: 10.0.0.2/30

Пакет 192.168.1.10 → 192.168.2.20:
  Исходный: | IP 192.168.1.10 → 192.168.2.20 | TCP | Data |
  В туннеле: | IP 203.0.113.1 → 198.51.100.1 (proto 47) | GRE (0x0800) | IP 192.168.1.10 → 192.168.2.20 | TCP | Data |
```

## **Особенности и проблемы**

### **MTU и фрагментация**

GRE добавляет 24 байта, поэтому пакет 1500 байт в туннеле превращается в 1524 байта:

```
MTU туннеля = 1500 − 24 = 1476 байт
TCP MSS     = 1476 − 40 = 1436 байт
```

Решения: `ip mtu 1476` и `ip tcp adjust-mss 1436` на туннельном интерфейсе. С IPsec накладные расходы ещё больше (MTU ~1400).

### **Рекурсивная маршрутизация**

Если маршрут до адреса конца туннеля начинает указывать в сам туннель, возникает петля: туннель падает с ошибкой «recursive routing». Маршрут до внешнего адреса партнёра должен идти через физический интерфейс.

### **NAT**

GRE не использует порты, поэтому PAT не может различить несколько GRE-туннелей за одним адресом. Многие домашние роутеры требуют «GRE passthrough».

## **Варианты GRE**

| Вариант              | Описание                                                       |
| -------------------- | -------------------------------------------------------------- |
| **GRE (point-to-point)** | Классический туннель между двумя адресами                  |
| **mGRE (multipoint)** | Один интерфейс для многих туннелей — основа DMVPN             |
| **GRETAP / EoGRE**   | Передача Ethernet-кадров (L2) поверх GRE                       |
| **ip6gre**           | GRE поверх IPv6                                                |
| **Enhanced GRE**     | Версия 1, используется PPTP                                    |
| **NVGRE**            | Виртуализация сетей в Hyper-V (как VXLAN)                      |
| **ERSPAN**           | Удалённое зеркалирование трафика поверх GRE                    |

## **GRE over IPsec**

GRE сам по себе не шифрует, а «чистый» IPsec (policy-based) не передаёт multicast и протоколы маршрутизации. Комбинация решает обе задачи:

```
| Внешний IP | ESP | GRE | Внутренний IP | Data | ESP Trailer |
```

Современная альтернатива — **VTI** (Virtual Tunnel Interface) — IPsec-туннель как интерфейс без GRE.

## **DMVPN**

Dynamic Multipoint VPN (Cisco) = **mGRE + NHRP + IPsec**:
- Филиалы подключаются к центральному хабу
- Филиалы строят прямые туннели друг к другу по требованию (spoke-to-spoke)
- NHRP сообщает, какой внешний адрес у нужного филиала

## **Примеры конфигурации**

### **Cisco IOS**

```
interface Tunnel0
 ip address 10.0.0.1 255.255.255.252
 ip mtu 1476
 ip tcp adjust-mss 1436
 tunnel source GigabitEthernet0/0
 tunnel destination 198.51.100.1
 tunnel key 100
 keepalive 10 3

ip route 192.168.2.0 255.255.255.0 10.0.0.2
```

```
show interfaces Tunnel0
show ip interface brief | include Tunnel
```

### **Linux**

```bash
# Router A
ip tunnel add gre1 mode gre local 203.0.113.1 remote 198.51.100.1 ttl 255 key 100
ip addr add 10.0.0.1/30 dev gre1
ip link set gre1 mtu 1476 up
ip route add 192.168.2.0/24 via 10.0.0.2

# L2-туннель (GRETAP), например для моста между двумя сетями
ip link add gretap1 type gretap local 203.0.113.1 remote 198.51.100.1
ip link set gretap1 master br0 up

# Разрешить GRE в iptables
iptables -A INPUT -p gre -s 198.51.100.1 -j ACCEPT
```

### **MikroTik RouterOS**

```
/interface gre add name=gre-to-B local-address=203.0.113.1 remote-address=198.51.100.1 keepalive=10s,3
/ip address add address=10.0.0.1/30 interface=gre-to-B
/ip route add dst-address=192.168.2.0/24 gateway=10.0.0.2
```

## **Безопасность GRE**

### **Риски**

1. **Нет шифрования** — трафик читается по пути
2. **Нет аутентификации** — можно внедрить пакеты, подделав внешний адрес источника
3. **Обход файрвола** — GRE-туннель может провести трафик мимо фильтров
4. **Key — не защита**, а только идентификатор туннеля

### **Защита**

- Использовать GRE только внутри IPsec (или выбрать WireGuard/VTI)
- Фильтровать протокол 47 на периметре: разрешать только от известных адресов
- Включать keepalive, чтобы туннель не был «поднят» вслепую

## **Сравнение туннелей**

| Характеристика    | GRE              | IP-in-IP         | VXLAN             | IPsec (туннельный режим) | WireGuard       |
| ----------------- | ---------------- | ---------------- | ----------------- | ------------------------ | --------------- |
| **Шифрование**    | Нет              | Нет              | Нет               | Да                       | Да              |
| **Multicast**     | Да               | Нет              | Да                | Нет (без GRE/VTI)        | Нет             |
| **Не-IP протоколы** | Да             | Нет              | L2 (Ethernet)     | Нет                      | Нет             |
| **Накладные расходы** | 24 байта     | 20 байт          | 50 байт           | 50–70 байт               | 60 байт         |
| **Проход через NAT** | Плохо         | Плохо            | Да (UDP)          | С NAT-T                  | Да (UDP)        |
