**HTTP/2** — вторая основная версия протокола HTTP, стандартизированная в 2015 году на основе протокола SPDY от Google. Семантика HTTP (методы, заголовки, коды ответа) осталась прежней, но изменился способ передачи: вместо текстовых сообщений — двоичные фреймы, вместо одного запроса за раз — множество параллельных потоков в одном TCP-соединении.

## **Основные характеристики**

| Параметр                    | Описание                                                                 |
| --------------------------- | ------------------------------------------------------------------------ |
| **Уровень OSI**             | Прикладной (Application Layer)                                           |
| **Транспорт**               | TCP                                                                      |
| **Порты**                   | 443 (h2, через TLS), 80 (h2c, без TLS — почти не используется)           |
| **Стандарт**                | RFC 9113 (ранее RFC 7540)                                                |
| **Сжатие заголовков**       | HPACK (RFC 7541)                                                         |
| **Согласование версии**     | ALPN в TLS (`h2`)                                                        |
| **Формат**                  | Двоичный                                                                 |
| **Предшественник**          | SPDY (Google)                                                            |

## **Проблемы HTTP/1.1, которые решает HTTP/2**

| Проблема HTTP/1.1                         | Решение в HTTP/2                         |
| ----------------------------------------- | ---------------------------------------- |
| Один запрос за раз на соединение           | Мультиплексирование потоков              |
| Браузер открывает по 6 соединений на домен | Одно соединение на домен                 |
| Head-of-line blocking на уровне HTTP       | Независимые потоки                       |
| Повторяющиеся текстовые заголовки (cookie, user-agent) | Сжатие HPACK                  |
| Текстовый формат, сложный разбор           | Двоичные фреймы                          |
| Обходные приёмы: спрайты, конкатенация, шардинг доменов | Больше не нужны             |

## **Основные понятия**

| Понятие         | Описание                                                          |
| --------------- | ----------------------------------------------------------------- |
| **Connection**  | Одно TCP (+TLS) соединение                                        |
| **Stream**      | Двунаправленный поток внутри соединения, = один запрос/ответ      |
| **Message**     | HTTP-запрос или ответ, состоит из фреймов                         |
| **Frame**       | Минимальная единица передачи, принадлежит одному потоку           |

```
TCP соединение
├── Stream 1: HEADERS → DATA → DATA     (GET /index.html)
├── Stream 3: HEADERS → DATA            (GET /style.css)
├── Stream 5: HEADERS → DATA → DATA     (GET /app.js)
└── Stream 0: SETTINGS, PING            (управление соединением)
```

Клиент открывает потоки с **нечётными** номерами, сервер (push) — с **чётными**. Поток 0 — управление соединением.

## **Структура фрейма**

| Поле                    | Размер (биты) | Описание                                  |
| ----------------------- | ------------- | ----------------------------------------- |
| **Length**              | 24            | Длина полезной нагрузки (по умолчанию до 16 384 байт) |
| **Type**                | 8             | Тип фрейма                                |
| **Flags**               | 8             | Флаги (END_STREAM, END_HEADERS и др.)     |
| **R**                   | 1             | Зарезервирован                            |
| **Stream Identifier**   | 31            | Номер потока                              |
| **Payload**             | Переменный    | Данные фрейма                             |

**Размер заголовка фрейма:** 9 байт

## **Типы фреймов**

| Код  | Фрейм             | Описание                                                    |
| ---- | ----------------- | ----------------------------------------------------------- |
| 0x0  | **DATA**          | Тело запроса/ответа                                         |
| 0x1  | **HEADERS**       | Заголовки (сжатые HPACK), открывает поток                   |
| 0x2  | **PRIORITY**      | Приоритет потока (устарел в RFC 9113)                       |
| 0x3  | **RST_STREAM**    | Немедленное закрытие потока                                 |
| 0x4  | **SETTINGS**      | Параметры соединения                                        |
| 0x5  | **PUSH_PROMISE**  | Сервер обещает отправить ресурс (Server Push)               |
| 0x6  | **PING**          | Проверка соединения, измерение RTT                          |
| 0x7  | **GOAWAY**        | Закрытие соединения                                         |
| 0x8  | **WINDOW_UPDATE** | Управление потоком (flow control)                           |
| 0x9  | **CONTINUATION**  | Продолжение заголовков                                      |

## **Псевдозаголовки**

Стартовая строка HTTP/1.1 заменена псевдозаголовками (начинаются с `:`):

```
HTTP/1.1:
GET /api/users HTTP/1.1
Host: example.com

HTTP/2:
:method: GET
:scheme: https
:authority: example.com
:path: /api/users
```

Ответ: `:status: 200`. Имена заголовков в HTTP/2 — **только строчные буквы**. Заголовки `Connection`, `Keep-Alive`, `Transfer-Encoding`, `Upgrade` запрещены.

## **HPACK — сжатие заголовков**

| Механизм               | Описание                                                     |
| ---------------------- | ------------------------------------------------------------ |
| **Статическая таблица** | 61 частый заголовок (`:method: GET`, `:status: 200`…) — передаётся индекс |
| **Динамическая таблица** | Заголовки текущего соединения запоминаются и затем ссылаются по индексу |
| **Кодирование Хаффмана** | Сжатие строковых значений                                  |

Повторяющиеся cookie и user-agent во втором и следующих запросах занимают всего несколько байт.

## **Параметры SETTINGS**

| Параметр                          | По умолчанию | Описание                                      |
| --------------------------------- | ------------ | --------------------------------------------- |
| `SETTINGS_HEADER_TABLE_SIZE`      | 4096         | Размер динамической таблицы HPACK             |
| `SETTINGS_ENABLE_PUSH`            | 1            | Разрешить Server Push                         |
| `SETTINGS_MAX_CONCURRENT_STREAMS` | без ограничения | Максимум одновременных потоков (обычно 100) |
| `SETTINGS_INITIAL_WINDOW_SIZE`    | 65 535       | Начальное окно flow control                   |
| `SETTINGS_MAX_FRAME_SIZE`         | 16 384       | Максимальный размер фрейма                    |
| `SETTINGS_MAX_HEADER_LIST_SIZE`   | без ограничения | Максимальный размер заголовков             |

## **Установление соединения**

```
Клиент                                          Сервер
  |--- TCP handshake ---------------------------->|
  |--- TLS ClientHello (ALPN: h2, http/1.1) ----->|
  |<-- TLS ServerHello (ALPN: h2) ----------------|
  |                                               |
  |--- Preface: "PRI * HTTP/2.0\r\n\r\nSM\r\n\r\n"|
  |--- SETTINGS -------------------------------->|
  |<-- SETTINGS ----------------------------------|
  |--- SETTINGS (ACK) --------------------------->|
  |<-- SETTINGS (ACK) ----------------------------|
  |                                               |
  |--- HEADERS (stream 1) ----------------------->|
  |--- HEADERS (stream 3) ----------------------->|
  |<-- HEADERS + DATA (stream 3) -----------------|  ответы в любом порядке
  |<-- HEADERS + DATA (stream 1) -----------------|
```

## **Коды ошибок (RST_STREAM / GOAWAY)**

| Код  | Название               | Описание                                  |
| ---- | ---------------------- | ----------------------------------------- |
| 0x0  | NO_ERROR               | Штатное закрытие                          |
| 0x1  | PROTOCOL_ERROR         | Нарушение протокола                       |
| 0x2  | INTERNAL_ERROR         | Внутренняя ошибка                         |
| 0x3  | FLOW_CONTROL_ERROR     | Нарушение flow control                    |
| 0x4  | SETTINGS_TIMEOUT       | Нет подтверждения SETTINGS                |
| 0x5  | STREAM_CLOSED          | Фрейм в закрытый поток                    |
| 0x6  | FRAME_SIZE_ERROR       | Неверный размер фрейма                    |
| 0x7  | REFUSED_STREAM         | Поток отклонён (можно повторить)          |
| 0x8  | CANCEL                 | Поток больше не нужен                     |
| 0x9  | COMPRESSION_ERROR      | Ошибка HPACK                              |
| 0xa  | CONNECT_ERROR          | Ошибка туннеля CONNECT                    |
| 0xb  | ENHANCE_YOUR_CALM      | Слишком много запросов                    |
| 0xc  | INADEQUATE_SECURITY    | Недостаточная защита TLS                  |
| 0xd  | HTTP_1_1_REQUIRED      | Нужно использовать HTTP/1.1               |

## **Server Push**

Сервер может заранее отправить ресурс (например, CSS), не дожидаясь запроса. На практике функция оказалась малополезной: **Chrome отключил её в 2022 году**. Замена — ответ **103 Early Hints** с заголовком `Link: rel=preload`.

## **Примеры использования**

### **Проверка поддержки**

```bash
curl -I --http2 https://example.com
curl -v --http2 https://example.com 2>&1 | grep ALPN

# Проверка через openssl
openssl s_client -connect example.com:443 -alpn h2 </dev/null 2>/dev/null | grep ALPN

# Нагрузочное тестирование
h2load -n 1000 -c 10 -m 10 https://example.com/
```

### **Nginx**

```nginx
server {
    listen 443 ssl;
    http2 on;              # nginx 1.25.1+, ранее: listen 443 ssl http2;
    server_name example.com;
    ssl_certificate     /etc/ssl/example.crt;
    ssl_certificate_key /etc/ssl/example.key;
}
```

### **Apache**

```apache
LoadModule http2_module modules/mod_http2.so
Protocols h2 http/1.1
```

### **Chrome DevTools**

Network → правый клик по заголовку таблицы → включить столбец **Protocol** (`h2`).

### **Wireshark**

```
http2
http2.type == 1
```

Для расшифровки TLS нужен `SSLKEYLOGFILE`.

## **Безопасность HTTP/2**

### **Известные атаки**

| Атака                       | Год  | Описание                                                    |
| --------------------------- | ---- | ----------------------------------------------------------- |
| **HPACK Bomb**              | 2016 | Маленькие заголовки раскрываются в огромные                 |
| **Ping/Settings Flood**     | 2019 | Сервер тратит ресурсы на ответы на служебные фреймы         |
| **Rapid Reset (CVE-2023-44487)** | 2023 | Открытие и мгновенная отмена потоков, рекордные DDoS-атаки |
| **CONTINUATION Flood**      | 2024 | Бесконечные фреймы CONTINUATION без END_HEADERS             |
| **Request Smuggling (H2.CL, H2.TE)** | — | Рассинхронизация при даунгрейде до HTTP/1.1 на прокси |

### **Защита**

- Обновлять серверы и прокси (nginx, Envoy, HAProxy)
- Ограничивать `max_concurrent_streams`, частоту RST_STREAM и размер заголовков
- Использовать HTTP/2 и до бэкенда, либо строго нормализовать запросы при даунгрейде

## **Ограничения HTTP/2**

1. **Head-of-line blocking на уровне TCP** — потеря одного пакета задерживает все потоки
2. **Установление соединения** — TCP + TLS = 2–3 RTT
3. **Смена сети** — при переходе с Wi-Fi на LTE соединение рвётся

Эти проблемы решает [HTTP/3](HTTP3.md) поверх QUIC.

## **Сравнение версий HTTP**

| Характеристика        | HTTP/1.1          | HTTP/2              | HTTP/3              |
| --------------------- | ----------------- | ------------------- | ------------------- |
| **Формат**            | Текстовый         | Двоичный            | Двоичный            |
| **Транспорт**         | TCP               | TCP                 | QUIC (UDP)          |
| **Мультиплексирование** | Нет             | Да                  | Да                  |
| **HOL blocking**      | HTTP и TCP        | Только TCP          | Нет                 |
| **Сжатие заголовков** | Нет               | HPACK               | QPACK               |
| **Шифрование**        | Опционально       | Фактически обязательно | Обязательно (TLS 1.3) |
| **Server Push**       | Нет               | Да (отключён в браузерах) | Да (почти не используется) |
