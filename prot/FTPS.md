**FTPS** (FTP over TLS/SSL, также FTP-SSL, FTP Secure) — классический протокол FTP с добавленным шифрованием TLS. Он защищает логин, пароль и данные, сохраняя при этом архитектуру FTP с раздельными каналами команд и данных. FTPS не нужно путать с [SFTP](SFTP.md): SFTP работает поверх SSH и устроен совершенно иначе, а FTPS — это тот же FTP, обёрнутый в TLS.

## **Основные характеристики**

| Параметр                    | Описание                                                                 |
| --------------------------- | ------------------------------------------------------------------------ |
| **Уровень OSI**             | Прикладной (Application Layer)                                           |
| **Транспорт**               | TCP                                                                      |
| **Порты**                   | Explicit: 21 (+ TLS); Implicit: 990 (команды), 989 (данные)              |
| **Стандарты**               | RFC 4217 (Explicit FTPS), RFC 2228 (команды безопасности FTP)            |
| **Шифрование**              | TLS/SSL                                                                  |
| **Аутентификация**          | Логин/пароль + X.509-сертификат сервера (и опционально клиента)          |
| **Каналы**                  | Управляющий + отдельный канал данных (как в FTP)                         |

## **Два режима FTPS**

| Режим          | Описание                                                            | Порт |
| -------------- | ------------------------------------------------------------------- | ---- |
| **Explicit (FTPES)** | Соединение открывается как обычный FTP на порту 21, затем клиент командой `AUTH TLS` переводит его в защищённый режим | 21 |
| **Implicit**   | TLS устанавливается сразу при подключении, до любых команд; устаревший | 990 |

**Explicit** — рекомендуемый современный вариант: один порт, гибкость, можно требовать TLS политикой сервера.

## **Команды защиты (RFC 2228 / 4217)**

| Команда         | Описание                                                       |
| --------------- | -------------------------------------------------------------- |
| **AUTH TLS**    | Начать TLS на управляющем канале (`AUTH SSL` — старый вариант)  |
| **PBSZ 0**      | Protection Buffer Size (для TLS всегда 0)                       |
| **PROT P**      | Защищать канал данных (P = Private, шифровать)                  |
| **PROT C**      | Канал данных без шифрования (C = Clear)                         |
| **CCC**         | Clear Command Channel — вернуть управляющий канал к открытому (для прохождения через NAT/ALG) |

## **Процесс (Explicit FTPS)**

```
Клиент                                          Сервер (порт 21)
  |--- TCP-соединение ---------------------------->|
  |<-- 220 Welcome --------------------------------|
  |--- AUTH TLS ---------------------------------->|
  |<-- 234 Proceed with negotiation ---------------|
  |==== TLS handshake (проверка сертификата) ======|
  |--- USER alice (зашифровано) ------------------>|
  |<-- 331 Password required ----------------------|
  |--- PASS ******** ----------------------------->|
  |<-- 230 Login successful -----------------------|
  |--- PBSZ 0 ------------------------------------>|
  |--- PROT P ------------------------------------>|  шифровать данные
  |--- PASV -------------------------------------->|
  |<-- 227 Entering Passive Mode (сервер:порт) ----|
  |==== отдельное TLS-соединение для данных =======|
  |<-- файл (зашифрован) --------------------------|
```

## **Каналы данных и NAT**

Как и в обычном FTP, канал данных открывается отдельно. Режимы:

| Режим           | Кто открывает канал данных | Проблема с файрволом/NAT          |
| --------------- | -------------------------- | --------------------------------- |
| **Active (PORT)** | Сервер → клиент          | Блокируется файрволом клиента     |
| **Passive (PASV)** | Клиент → сервер         | Нужен диапазон портов на сервере  |

С FTPS добавляется сложность: при шифровании управляющего канала **FTP ALG на маршрутизаторе не видит команды PASV/PORT** и не может автоматически открыть порты данных. Решения:
- Настроить фиксированный **диапазон пассивных портов** и внешний адрес на FTPS-сервере, открыть эти порты на файрволе
- Использовать команду **CCC** (но тогда управляющий канал после входа становится открытым)

## **Примеры использования**

### **Клиент curl**

```bash
# Explicit FTPS
curl --ftp-ssl --ssl-reqd -u alice:secret ftp://ftp.example.com/file.txt -o file.txt

# Загрузка
curl --ftp-ssl --ssl-reqd -T backup.zip -u alice:secret ftp://ftp.example.com/backups/

# Implicit FTPS (схема ftps:// и порт 990)
curl -u alice:secret ftps://ftp.example.com:990/file.txt -o file.txt
```

### **lftp**

```bash
lftp -u alice,secret ftp.example.com <<'EOF'
set ftp:ssl-force true
set ftp:ssl-protect-data true
set ssl:verify-certificate yes
ls
get file.txt
bye
EOF
```

### **Проверка через openssl**

```bash
openssl s_client -connect ftp.example.com:21 -starttls ftp
openssl s_client -connect ftp.example.com:990    # implicit
```

### **Графические клиенты**

FileZilla, WinSCP, Cyberduck поддерживают FTPS. В FileZilla: протокол «FTP», шифрование — «Требовать явный FTP через TLS».

### **Сервер vsftpd (Linux)**

```
# /etc/vsftpd.conf
ssl_enable=YES
force_local_logins_ssl=YES
force_local_data_ssl=YES
ssl_tlsv1_2=YES
ssl_sslv2=NO
ssl_sslv3=NO
require_ssl_reuse=NO
rsa_cert_file=/etc/ssl/certs/vsftpd.pem
rsa_private_key_file=/etc/ssl/private/vsftpd.key

# Пассивные порты для прохождения через файрвол
pasv_enable=YES
pasv_min_port=40000
pasv_max_port=40100
pasv_address=203.0.113.10
```

```bash
# Открыть порты на файрволе
iptables -A INPUT -p tcp --dport 21 -j ACCEPT
iptables -A INPUT -p tcp --dport 40000:40100 -j ACCEPT
```

### **Сервер FileZilla Server (Windows)**

В настройках: вкладка TLS → создать/импортировать сертификат → «Require explicit FTP over TLS».

### **Wireshark**

```
ftp                 # команды управляющего канала (до AUTH TLS)
ftp-data
tls && tcp.port == 21
```

После `AUTH TLS` содержимое команд зашифровано; видны только TLS-записи.

## **Безопасность FTPS**

### **Преимущества**

- Шифрование логина, пароля и данных
- Проверка подлинности сервера по сертификату X.509
- Можно требовать клиентский сертификат (взаимная аутентификация)
- Совместимость с существующей инфраструктурой FTP

### **Недостатки и риски**

1. **Сложность с файрволами/NAT** — главная проблема (отдельный канал данных + шифрование)
2. **Много открытых портов** — управляющий + диапазон пассивных
3. **Старые реализации** — поддержка SSLv3/TLS 1.0, слабые шифры
4. **Implicit FTPS** — устаревший режим
5. **Самоподписанные сертификаты** — клиенты часто отключают проверку

### **Рекомендации**

- Только TLS 1.2/1.3, отключить SSLv2/SSLv3/TLS 1.0/1.1
- Доверенный сертификат (не самоподписанный) и проверка на клиенте
- Фиксированный диапазон пассивных портов + `pasv_address`
- Там, где возможно, предпочесть [SFTP](SFTP.md) — один порт, проще через NAT

## **Сравнение FTPS, SFTP и FTP**

| Характеристика      | FTP                 | FTPS                      | SFTP                       |
| ------------------- | ------------------- | ------------------------- | -------------------------- |
| **Основа**          | —                   | FTP + TLS                 | SSH                        |
| **Шифрование**      | Нет                 | Да (TLS)                  | Да (SSH)                   |
| **Порты**           | 21 + данные         | 21/990 + диапазон данных  | 22                         |
| **Каналы**          | Два                 | Два                       | Один                       |
| **Через NAT/файрвол** | Сложно            | Сложнее всего             | Просто                     |
| **Аутентификация сервера** | Нет          | Сертификат X.509          | Host key                   |
| **Аутентификация клиента** | Пароль        | Пароль + сертификат       | Пароль + ключи SSH         |
| **Когда выбирать**  | Никогда             | Нужна совместимость с FTP и сертификаты X.509 | Предпочтительно в большинстве случаев |
