**Modbus** — один из старейших и самых распространённых промышленных протоколов, созданный Modicon в 1979 году для программируемых логических контроллеров (ПЛК). Он простой, открытый и работает по модели ведущий-ведомый (master-slave): ведущее устройство (SCADA, ПЛК) опрашивает датчики, приводы и счётчики. Modbus существует в последовательных вариантах (RTU, ASCII) и сетевом (Modbus TCP).

## **Основные характеристики**

| Параметр                    | Описание                                                                 |
| --------------------------- | ------------------------------------------------------------------------ |
| **Уровень OSI**             | Прикладной (Application Layer)                                           |
| **Модель**                  | Master-Slave (клиент-сервер в Modbus TCP)                                |
| **Варианты**                | Modbus RTU, Modbus ASCII (по RS-232/RS-485), Modbus TCP                   |
| **Порт (TCP)**              | 502                                                                      |
| **Адресация ведомых**       | 1–247 (0 = broadcast)                                                    |
| **Данные**                  | Big-endian (старший байт первым)                                        |
| **Безопасность**            | Исторически отсутствует; есть Modbus/TCP Security (TLS)                   |

## **Варианты Modbus**

| Вариант          | Среда             | Особенности                                   |
| ---------------- | ----------------- | --------------------------------------------- |
| **Modbus RTU**   | RS-232 / RS-485   | Двоичный, компактный, контроль CRC            |
| **Modbus ASCII** | RS-232 / RS-485   | Текстовый (ASCII-hex), менее эффективный, LRC |
| **Modbus TCP**   | Ethernet / IP     | Поверх TCP (порт 502), без CRC (его обеспечивает TCP) |
| **Modbus TCP Security** | Ethernet   | Modbus TCP поверх TLS (порт 802)              |

## **Модель данных**

Modbus оперирует четырьмя таблицами данных:

| Таблица                 | Тип        | Доступ         | Адреса          | Функция                       |
| ----------------------- | ---------- | -------------- | --------------- | ----------------------------- |
| **Discrete Inputs**     | 1 бит      | Чтение         | 10001–19999     | Дискретные входы (датчики)    |
| **Coils**               | 1 бит      | Чтение/запись  | 00001–09999     | Дискретные выходы (реле)      |
| **Input Registers**     | 16 бит     | Чтение         | 30001–39999     | Аналоговые входы              |
| **Holding Registers**   | 16 бит     | Чтение/запись  | 40001–49999     | Параметры, уставки            |

Классическая нумерация (с 1) отличается от адреса в кадре (с 0): регистр 40001 = адрес 0 в сообщении.

## **Коды функций**

| Код (hex) | Функция                              | Таблица              |
| --------- | ------------------------------------ | -------------------- |
| 0x01      | Read Coils                           | Coils                |
| 0x02      | Read Discrete Inputs                 | Discrete Inputs      |
| 0x03      | Read Holding Registers               | Holding Registers    |
| 0x04      | Read Input Registers                 | Input Registers      |
| 0x05      | Write Single Coil                    | Coils                |
| 0x06      | Write Single Register                | Holding Registers    |
| 0x0F      | Write Multiple Coils                 | Coils                |
| 0x10      | Write Multiple Registers             | Holding Registers    |
| 0x16      | Mask Write Register                  | Holding Registers    |
| 0x17      | Read/Write Multiple Registers        | Holding Registers    |
| 0x2B      | Read Device Identification           | —                    |

## **Структура сообщения**

### **PDU (общая часть)**

```
| Function Code (1 байт) | Data (переменный) |
```

### **Modbus RTU (последовательный кадр)**

```
| Адрес (1) | Function Code (1) | Data | CRC-16 (2) |
```

Кадры разделяются паузой не менее 3,5 символов тишины.

### **Modbus TCP (кадр с MBAP-заголовком)**

```
| MBAP Header (7 байт) | Function Code (1) | Data |
```

| Поле MBAP               | Размер | Описание                                |
| ----------------------- | ------ | --------------------------------------- |
| **Transaction ID**      | 2      | Сопоставление запроса и ответа          |
| **Protocol ID**         | 2      | 0 (Modbus)                              |
| **Length**              | 2      | Длина оставшихся байтов                 |
| **Unit ID**             | 1      | Адрес ведомого (для шлюзов на RS-485)   |

В Modbus TCP нет CRC — целостность обеспечивает сам TCP.

## **Пример обмена (Read Holding Registers)**

```
Запрос (прочитать 2 регистра начиная с 40001):
Master → Slave:  11 03 006B 0002 <CRC>
  11   = адрес ведомого (17)
  03   = Read Holding Registers
  006B = стартовый адрес (регистр 40108? → адрес 0x006B)
  0002 = количество регистров

Ответ:
Slave → Master:  11 03 04 022B 0000 <CRC>
  04   = количество байт данных
  022B = значение регистра 1 (555)
  0000 = значение регистра 2 (0)
```

## **Коды ошибок (Exception)**

При ошибке ведомый возвращает код функции с установленным старшим битом (например, `0x03` → `0x83`) и код исключения:

| Код | Исключение                     | Описание                                 |
| --- | ------------------------------ | ---------------------------------------- |
| 01  | Illegal Function               | Функция не поддерживается                |
| 02  | Illegal Data Address           | Недопустимый адрес регистра              |
| 03  | Illegal Data Value             | Недопустимое значение                    |
| 04  | Slave Device Failure           | Ошибка устройства                        |
| 05  | Acknowledge                    | Запрос принят, обработка идёт            |
| 06  | Slave Device Busy              | Устройство занято                        |
| 08  | Memory Parity Error            | Ошибка чётности памяти                   |
| 0A  | Gateway Path Unavailable       | Шлюз не нашёл путь                        |
| 0B  | Gateway Target Failed to Respond | Целевое устройство не ответило          |

## **Примеры использования**

### **Python (pymodbus) — клиент TCP**

```python
from pymodbus.client import ModbusTcpClient

client = ModbusTcpClient("192.168.1.50", port=502)
client.connect()

# Прочитать 2 holding-регистра начиная с 0
rr = client.read_holding_registers(address=0, count=2, slave=17)
print(rr.registers)

# Записать значение 1234 в регистр 0
client.write_register(address=0, value=1234, slave=17)

# Включить реле (coil)
client.write_coil(address=5, value=True, slave=17)

client.close()
```

### **Python — последовательный (RTU)**

```python
from pymodbus.client import ModbusSerialClient

client = ModbusSerialClient(port="/dev/ttyUSB0", baudrate=9600,
                            parity="N", stopbits=1, bytesize=8)
client.connect()
rr = client.read_input_registers(address=0, count=4, slave=1)
print(rr.registers)
client.close()
```

### **CLI (mbpoll)**

```bash
# Прочитать 10 holding-регистров по TCP
mbpoll -m tcp -a 17 -r 1 -c 10 192.168.1.50

# Записать значение в регистр по RS-485
mbpoll -m rtu -b 9600 -a 1 -r 1 /dev/ttyUSB0 1234
```

### **Диагностика сети**

```bash
nmap -p 502 --script modbus-discover 192.168.1.0/24
```

### **Wireshark**

```

```

## **Безопасность**

### **Почему Modbus опасен в современных сетях**

1. **Нет аутентификации** — любой, кто может отправить пакет, управляет оборудованием
2. **Нет шифрования** — команды и данные видны в сети
3. **Нет контроля целостности** (кроме CRC от случайных ошибок, не от атак)
4. **Критические последствия** — запись в регистр может остановить насос, открыть клапан, изменить уставку
5. **Legacy-устройства** живут десятилетиями без обновлений

### **Защита (принцип «безопасность через сегментацию»)**

- **Изоляция OT-сети** от IT и интернета (модель Purdue, зоны и каналы по IEC 62443)
- **Файрволы с DPI для Modbus** — разрешать только нужные функции и адреса (например, запретить запись с инженерных станций в рабочее время)
- **Modbus/TCP Security** (TLS, порт 802) там, где оборудование поддерживает
- **Односторонние шлюзы (data diode)** для передачи телеметрии наружу
- Мониторинг аномалий (неожиданные команды записи, новые master-устройства)
- VPN между площадками, никогда не выставлять порт 502 в интернет

## **Связанные промышленные протоколы**

| Протокол        | Описание                                                       |
| --------------- | -------------------------------------------------------------- |
| **Modbus**      | Простой, master-slave, регистры                                |
| **DNP3**        | Энергетика, с метками времени и приоритетами событий           |
| **EtherNet/IP** | CIP поверх Ethernet (Rockwell/Allen-Bradley)                   |
| **PROFINET**    | Промышленный Ethernet (Siemens)                                |
| **OPC UA**      | Современный, с безопасностью и информационными моделями        |
| **BACnet**      | Автоматизация зданий (HVAC)                                    |

## **Сравнение вариантов Modbus**

| Характеристика    | Modbus RTU            | Modbus ASCII         | Modbus TCP               |
| ----------------- | --------------------- | -------------------- | ------------------------ |
| **Среда**         | RS-485/232            | RS-485/232           | Ethernet/IP              |
| **Кодирование**   | Двоичное              | ASCII-hex            | Двоичное                 |
| **Контроль ошибок** | CRC-16              | LRC                  | TCP checksum             |
| **Скорость**      | Высокая               | Низкая               | Высокая                  |
| **Длина сети**    | До 1200 м (RS-485)    | До 1200 м            | Как Ethernet             |
| **Количество узлов** | 32–247 на шине     | 32–247               | Ограничено сетью         |
| **Распространённость** | Очень высокая    | Редко                | Растёт                   |
