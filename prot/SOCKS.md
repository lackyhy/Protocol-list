**SOCKS** (Socket Secure) — протокол прокси-сервера сеансового уровня, который ретранслирует произвольные TCP-соединения (а в версии 5 — и UDP) между клиентом и сервером. В отличие от HTTP-прокси, SOCKS не разбирает трафик приложения: ему всё равно, что передаётся — HTTP, SSH, IMAP или игровой протокол. SOCKS5 используется в Tor, SSH-туннелях (`ssh -D`), браузерах и многих прокси-сервисах.

## **Основные характеристики**

| Параметр                    | Описание                                                                 |
| --------------------------- | ------------------------------------------------------------------------ |
| **Уровень OSI**             | Сеансовый (между прикладным и транспортным)                              |
| **Транспорт**               | TCP (управление), UDP (UDP ASSOCIATE в SOCKS5)                           |
| **Порт**                    | 1080 (стандартный), Tor — 9050                                           |
| **Версии**                  | SOCKS4, SOCKS4a, SOCKS5 (RFC 1928)                                       |
| **Аутентификация**          | SOCKS5: нет, логин/пароль (RFC 1929), GSSAPI (RFC 1961)                  |
| **Шифрование**              | Нет (трафик передаётся как есть)                                         |
| **Протоколы приложений**    | Любые поверх TCP/UDP                                                     |

## **Версии SOCKS**

| Возможность                  | SOCKS4         | SOCKS4a          | SOCKS5                     |
| ---------------------------- | -------------- | ---------------- | -------------------------- |
| **TCP CONNECT**              | Да             | Да               | Да                         |
| **TCP BIND** (входящие)      | Да             | Да               | Да                         |
| **UDP**                      | Нет            | Нет              | Да (UDP ASSOCIATE)         |
| **IPv6**                     | Нет            | Нет              | Да                         |
| **Доменные имена (DNS на прокси)** | Нет      | Да               | Да                         |
| **Аутентификация**           | Только User ID | Только User ID   | Логин/пароль, GSSAPI       |

## **Как работает SOCKS5**

```
Клиент                         SOCKS5-прокси (1080)                Сервер
  |                                    |                              |
  |--- TCP-соединение --------------->|                              |
  |--- Приветствие: методы [0x00, 0x02]->|                            |
  |<-- Выбран метод 0x02 (логин/пароль)-|                            |
  |--- Логин и пароль --------------->|                              |
  |<-- 0x00 (успех) ------------------|                              |
  |--- CONNECT example.com:443 ------>|                              |
  |                                    |--- TCP-соединение --------->|
  |<-- Ответ 0x00 (успех), BND.ADDR --|                              |
  |                                    |                              |
  |<========== данные (TLS и т.д.) ===|=============================>|
```

### **1. Приветствие (выбор метода)**

| Поле       | Размер | Описание                            |
| ---------- | ------ | ----------------------------------- |
| VER        | 1      | 0x05                                |
| NMETHODS   | 1      | Количество методов                  |
| METHODS    | 1–255  | Список методов                      |

| Метод | Описание                         |
| ----- | -------------------------------- |
| 0x00  | Без аутентификации               |
| 0x01  | GSSAPI                           |
| 0x02  | Логин/пароль                     |
| 0xFF  | Нет подходящих методов           |

### **2. Запрос**

| Поле       | Размер     | Описание                                         |
| ---------- | ---------- | ------------------------------------------------ |
| VER        | 1          | 0x05                                             |
| CMD        | 1          | 0x01 CONNECT, 0x02 BIND, 0x03 UDP ASSOCIATE      |
| RSV        | 1          | 0x00                                             |
| ATYP       | 1          | 0x01 IPv4, 0x03 домен, 0x04 IPv6                 |
| DST.ADDR   | переменный | Адрес назначения                                 |
| DST.PORT   | 2          | Порт назначения                                  |

### **3. Ответ — коды REP**

| Код  | Описание                                    |
| ---- | ------------------------------------------- |
| 0x00 | Успех                                       |
| 0x01 | Общий сбой SOCKS-сервера                    |
| 0x02 | Соединение запрещено правилами              |
| 0x03 | Сеть недоступна                             |
| 0x04 | Хост недоступен                             |
| 0x05 | Соединение отклонено                        |
| 0x06 | TTL истёк                                   |
| 0x07 | Команда не поддерживается                   |
| 0x08 | Тип адреса не поддерживается                |

## **UDP ASSOCIATE**

Для UDP клиент через TCP просит прокси открыть UDP-порт. Затем UDP-датаграммы отправляются на этот порт с небольшим заголовком (адрес назначения). Пока TCP-соединение открыто, связь действует. Используется для DNS, VoIP и игр, но поддерживается не всеми клиентами и серверами.

## **DNS и утечки**

| Схема          | Где резолвятся имена | Утечка DNS                   |
| -------------- | -------------------- | ---------------------------- |
| `socks5://`    | Обычно на клиенте    | Да — запросы идут мимо прокси |
| `socks5h://`   | На прокси            | Нет                          |
| `socks4a://`   | На прокси            | Нет                          |

В Firefox — флажок «Отправлять DNS-запросы через прокси при использовании SOCKS v5».

## **Примеры использования**

### **SSH как SOCKS5-прокси (динамический проброс)**

```bash
ssh -D 1080 -N -C user@server.example.com
# Теперь localhost:1080 — SOCKS5-прокси, трафик идёт через server.example.com
```

### **curl**

```bash
curl --socks5-hostname 127.0.0.1:1080 https://ifconfig.me
curl -x socks5h://user:pass@proxy.example.com:1080 https://example.com
```

### **Переменные окружения**

```bash
export ALL_PROXY=socks5h://127.0.0.1:1080
git -c http.proxy=socks5h://127.0.0.1:1080 clone https://github.com/user/repo
```

### **proxychains — для приложений без поддержки прокси**

```
# /etc/proxychains4.conf
[ProxyList]
socks5 127.0.0.1 1080
```

```bash
proxychains4 nmap -sT -Pn 10.0.0.5
proxychains4 ssh user@internal-host
```

### **SSH через SOCKS-прокси**

```
# ~/.ssh/config
Host internal
    ProxyCommand nc -X 5 -x 127.0.0.1:1080 %h %p
```

### **Python (requests)**

```python
# pip install requests[socks]
import requests
proxies = {"https": "socks5h://127.0.0.1:1080"}
print(requests.get("https://ifconfig.me", proxies=proxies).text)
```

### **Сервер Dante (Linux)**

```
# /etc/danted.conf
logoutput: syslog
internal: eth0 port = 1080
external: eth0
socksmethod: username
user.privileged: root
user.unprivileged: nobody

client pass {
    from: 10.0.0.0/8 to: 0.0.0.0/0
}
socks pass {
    from: 10.0.0.0/8 to: 0.0.0.0/0
    command: connect udpassociate
}
```

### **Tor**

```bash
curl --socks5-hostname 127.0.0.1:9050 https://check.torproject.org/api/ip
```

### **Wireshark**

```
socks
tcp.port == 1080
```

## **Безопасность**

### **Риски**

1. **Нет шифрования** — между клиентом и прокси всё передаётся открыто (включая логин/пароль SOCKS5)
2. **Открытые прокси** — используются для спама, атак и сокрытия источника
3. **Утечки DNS** при `socks5://` вместо `socks5h://`
4. **Обход файрволов** — SOCKS-туннели через SSH позволяют обойти сетевые политики
5. **Недоверенные прокси** видят весь незашифрованный трафик

### **Рекомендации**

- Не выставлять SOCKS-сервер в интернет без аутентификации и ACL
- Шифровать канал до прокси (SSH, TLS-обёртка, VPN)
- Использовать HTTPS поверх прокси
- Использовать `socks5h` для защиты от утечек DNS

## **Сравнение SOCKS5 и HTTP-прокси**

| Характеристика         | SOCKS5                        | HTTP-прокси                       |
| ---------------------- | ----------------------------- | --------------------------------- |
| **Уровень**            | Сеансовый                     | Прикладной                        |
| **Протоколы**          | Любые TCP и UDP               | HTTP; другие — через CONNECT (только TCP) |
| **UDP**                | Да                            | Нет                               |
| **Разбор трафика**     | Нет                           | Да (кэширование, фильтрация, заголовки) |
| **Кэширование**        | Нет                           | Да                                |
| **Аутентификация**     | Логин/пароль, GSSAPI          | Basic, Digest, NTLM, Negotiate    |
| **Типичное применение** | Tor, SSH-туннели, P2P, игры  | Корпоративный веб-доступ, кэш    |
