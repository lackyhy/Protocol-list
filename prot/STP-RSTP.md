**STP** (Spanning Tree Protocol) — протокол канального уровня, который предотвращает петли в сетях с резервными связями между коммутаторами. STP строит логическое дерево без петель, блокируя лишние порты, а при обрыве основной связи включает резервную. **RSTP** (Rapid STP) — ускоренная версия с конвергенцией за секунды вместо десятков секунд.

## **Основные характеристики**

| Параметр                    | Описание                                                                 |
| --------------------------- | ------------------------------------------------------------------------ |
| **Уровень OSI**             | Канальный (Data Link Layer)                                              |
| **Стандарты**               | IEEE 802.1D (STP), 802.1w (RSTP), 802.1s (MSTP); сейчас всё в 802.1Q     |
| **Сообщения**               | BPDU (Bridge Protocol Data Unit)                                         |
| **Адрес рассылки**          | `01:80:C2:00:00:00`                                                      |
| **Алгоритм**                | Spanning Tree Algorithm (Радия Перлман)                                  |
| **Конвергенция**            | STP: 30–50 секунд, RSTP: 1–3 секунды                                     |

## **Проблема петель**

Без STP при двух связях между коммутаторами возникают:

1. **Broadcast Storm** — широковещательный кадр бесконечно ходит по кругу и размножается
2. **Нестабильность таблицы MAC** — один MAC «прыгает» между портами
3. **Дублирование кадров** — получатель получает копии

У Ethernet-кадра нет TTL, поэтому петля не затухает сама и за секунды кладёт сеть.

## **Как работает STP**

### **1. Выбор корневого моста (Root Bridge)**

Коммутатор с наименьшим **Bridge ID** становится корнем.

```
Bridge ID = Priority (2 байта) + MAC-адрес (6 байт)

Priority по умолчанию: 32768
Шаг изменения:         4096 (с учётом Extended System ID = номер VLAN)
```

### **2. Выбор корневых портов (Root Port)**

На каждом некорневом коммутаторе выбирается один порт с наименьшей стоимостью пути до корня.

### **3. Выбор назначенных портов (Designated Port)**

На каждом сегменте выбирается один порт, ближайший к корню. Все порты корня — назначенные.

### **4. Блокировка остальных**

Оставшиеся порты переводятся в состояние **Blocking** (RSTP — **Alternate/Backup**).

### **Критерии выбора (по порядку)**

1. Наименьший Root Bridge ID
2. Наименьшая стоимость пути до корня (Root Path Cost)
3. Наименьший Bridge ID отправителя
4. Наименьший Port ID отправителя (приоритет + номер порта)

### **Стоимость портов**

| Скорость  | 802.1D (старая) | 802.1t (длинная) |
| --------- | --------------- | ---------------- |
| 10 Мбит/с | 100             | 2 000 000        |
| 100 Мбит/с | 19             | 200 000          |
| 1 Гбит/с  | 4               | 20 000           |
| 10 Гбит/с | 2               | 2 000            |
| 100 Гбит/с | —              | 200              |

### **Пример топологии**

```
            [SW1] Root Bridge (priority 4096)
           DP /    \ DP
             /      \
         RP /        \ RP
        [SW2]--------[SW3]
            DP      BLK
```

Связь SW2–SW3 логически отключена на стороне SW3, петли нет. Если связь SW1–SW3 оборвётся, заблокированный порт перейдёт в Forwarding.

## **Состояния портов STP (802.1D)**

| Состояние      | Пересылка данных | Изучение MAC | Приём BPDU | Длительность    |
| -------------- | ---------------- | ------------ | ---------- | --------------- |
| **Disabled**   | Нет              | Нет          | Нет        | —               |
| **Blocking**   | Нет              | Нет          | Да         | до 20 с (Max Age) |
| **Listening**  | Нет              | Нет          | Да         | 15 с (Forward Delay) |
| **Learning**   | Нет              | Да           | Да         | 15 с (Forward Delay) |
| **Forwarding** | Да               | Да           | Да         | —               |

### **Таймеры STP**

| Таймер            | Значение по умолчанию | Описание                                  |
| ----------------- | --------------------- | ----------------------------------------- |
| **Hello Time**    | 2 с                   | Интервал отправки BPDU корнем             |
| **Forward Delay** | 15 с                  | Время в Listening и в Learning            |
| **Max Age**       | 20 с                  | Сколько хранить последнюю BPDU            |

## **RSTP (802.1w)**

### **Роли портов**

| Роль            | Описание                                                    |
| --------------- | ----------------------------------------------------------- |
| **Root**        | Лучший путь к корню                                         |
| **Designated**  | Пересылает трафик в сегмент                                 |
| **Alternate**   | Резерв для Root-порта (другой путь к корню)                 |
| **Backup**      | Резерв для Designated-порта в том же сегменте               |
| **Disabled**    | Выключен                                                    |

### **Состояния портов**

RSTP сокращает состояния до трёх: **Discarding**, **Learning**, **Forwarding**.

### **Почему RSTP быстрее**

1. **Proposal/Agreement** — соседи договариваются о переходе в Forwarding без таймеров
2. **Edge-порты** — порты к конечным устройствам сразу в Forwarding (аналог PortFast)
3. **Alternate-порт** заранее известен и включается мгновенно
4. **Каждый коммутатор** отправляет BPDU сам, а не только ретранслирует от корня
5. Потеря соседа определяется за **3 Hello** (6 секунд), а не за Max Age

### **Типы каналов**

| Тип           | Описание                                         |
| ------------- | ------------------------------------------------ |
| **Point-to-point** | Full-duplex между двумя коммутаторами (быстрый переход) |
| **Shared**    | Half-duplex, хаб (работает как классический STP) |
| **Edge**      | Конечное устройство                              |

## **Варианты STP**

| Протокол     | Стандарт    | Экземпляры дерева          | Особенности                            |
| ------------ | ----------- | -------------------------- | -------------------------------------- |
| **STP**      | 802.1D      | Один на всю сеть           | Медленная конвергенция                 |
| **PVST+**    | Cisco       | Один на каждый VLAN        | Балансировка VLAN по разным путям      |
| **RSTP**     | 802.1w      | Один на всю сеть           | Быстрая конвергенция                   |
| **Rapid PVST+** | Cisco    | Один на каждый VLAN        | RSTP + per-VLAN, по умолчанию на Cisco |
| **MSTP**     | 802.1s      | Несколько, VLAN группируются | Масштабируемость, стандарт          |

## **Механизмы защиты**

| Механизм         | Описание                                                            |
| ---------------- | ------------------------------------------------------------------- |
| **PortFast**     | Порт к хосту сразу в Forwarding                                     |
| **BPDU Guard**   | Выключает PortFast-порт при получении BPDU (кто-то подключил коммутатор) |
| **BPDU Filter**  | Не отправлять и не принимать BPDU на порту (осторожно — риск петли) |
| **Root Guard**   | Запрещает порту становиться Root-портом (защита корня)              |
| **Loop Guard**   | Не переводит порт в Forwarding при пропаже BPDU (однонаправленный канал) |
| **UDLD**         | Обнаружение однонаправленных оптических каналов (Cisco)             |

## **Примеры конфигурации**

### **Cisco IOS**

```
spanning-tree mode rapid-pvst

! Сделать коммутатор корнем для VLAN 10 и 20
spanning-tree vlan 10,20 priority 4096
! или
spanning-tree vlan 10,20 root primary

! Порт к рабочей станции
interface GigabitEthernet0/5
 spanning-tree portfast
 spanning-tree bpduguard enable

! Защита корня на портах к коммутаторам доступа
interface GigabitEthernet0/24
 spanning-tree guard root
```

### **Проверка**

```
show spanning-tree
show spanning-tree vlan 10
show spanning-tree summary
show spanning-tree interface Gi0/1 detail
```

### **Linux bridge**

```bash
ip link add br0 type bridge stp_state 1
ip link set eth0 master br0
ip link set eth1 master br0
bridge link show
# Для RSTP используется mstpd
```

### **Wireshark**

```
stp
stp.type == 0x02   # RST BPDU
```

## **Безопасность STP**

### **Атаки**

1. **Root Bridge Attack** — атакующий отправляет BPDU с приоритетом 0 и становится корнем, трафик идёт через него
2. **BPDU Flood** — постоянные перестроения дерева (DoS)
3. **TCN-атака** — частые Topology Change вызывают очистку MAC-таблиц и flooding

### **Защита**

- BPDU Guard на всех access-портах
- Root Guard на портах, за которыми не может быть корня
- Явно задать приоритет корня и резервного корня
- Отключить STP-обработку на портах к недоверенным устройствам только вместе с BPDU Guard

## **Сравнение STP и RSTP**

| Характеристика    | STP (802.1D)                      | RSTP (802.1w)                     |
| ----------------- | --------------------------------- | --------------------------------- |
| **Конвергенция**  | 30–50 секунд                      | 1–3 секунды                       |
| **Состояния**     | 5                                 | 3                                 |
| **Резервные роли** | Нет (просто Blocking)            | Alternate, Backup                 |
| **BPDU**          | Генерирует корень                 | Каждый коммутатор                 |
| **Edge-порты**    | PortFast (проприетарно)           | Встроено                          |
| **Совместимость** | —                                 | Работает с STP (в режиме STP)     |
