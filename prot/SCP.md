**SCP** (Secure Copy Protocol) — простой протокол копирования файлов между хостами через SSH. Он появился как защищённая замена команде `rcp` из BSD и умеет только одно — скопировать файлы и каталоги в одну сторону. Сам протокол считается устаревшим: начиная с OpenSSH 9.0 утилита `scp` по умолчанию работает поверх SFTP, сохранив привычный синтаксис.

## **Основные характеристики**

| Параметр                    | Описание                                                                 |
| --------------------------- | ------------------------------------------------------------------------ |
| **Уровень OSI**             | Прикладной (Application Layer)                                           |
| **Транспорт**               | SSH (TCP)                                                                |
| **Порт**                    | 22                                                                       |
| **Стандарт**                | Нет формального стандарта (основан на BSD rcp)                          |
| **Аутентификация**          | Средствами SSH                                                           |
| **Шифрование**              | Средствами SSH                                                           |
| **Операции**                | Только копирование                                                       |
| **Статус**                  | Устаревший протокол, утилита `scp` переведена на SFTP (OpenSSH 9.0+)    |

## **Как работает SCP (классический протокол)**

Клиент подключается по SSH и запускает на сервере команду `scp` в специальном режиме:

| Флаг     | Режим                                  |
| -------- | -------------------------------------- |
| `scp -t` | **to** — сервер принимает файлы        |
| `scp -f` | **from** — сервер отправляет файлы     |

Дальше стороны обмениваются простыми текстовыми заголовками и данными через stdin/stdout.

### **Сообщения протокола**

| Сообщение                     | Описание                                    |
| ----------------------------- | ------------------------------------------- |
| `C0644 1234 file.txt\n`       | Начало файла: права, размер, имя            |
| `D0755 0 dirname\n`           | Вход в каталог                              |
| `E\n`                         | Выход из каталога                           |
| `T1700000000 0 1700000000 0\n` | Время изменения и доступа (флаг `-p`)      |
| `\0`                          | Подтверждение (OK)                          |
| `\1` + сообщение              | Предупреждение                              |
| `\2` + сообщение              | Фатальная ошибка                            |

### **Пример обмена (загрузка файла)**

```
Клиент                                    Сервер (scp -t /tmp)
  |-- SSH: exec "scp -t /tmp" --------------->|
  |<-- \0 ------------------------------------|  готов
  |-- C0644 11 hello.txt\n ------------------>|
  |<-- \0 ------------------------------------|
  |-- "Hello world" + \0 -------------------->|
  |<-- \0 ------------------------------------|
  |-- закрыть канал ------------------------->|
```

## **Почему классический SCP устарел**

1. **Оболочка на сервере** — имена файлов интерпретируются удалённой shell, что ведёт к уязвимостям
2. **Сервер доверяет клиенту и наоборот** — клиент почти не проверял, что прислал сервер
3. **CVE-2019-6111, CVE-2019-6110** — вредоносный сервер мог перезаписать произвольные файлы у клиента
4. **CVE-2020-15778** — инъекция команд через имя файла
5. **Нет докачки, списка файлов, удаления**
6. **Нет развития** — протокол не стандартизован и не расширяется

## **Примеры использования**

### **Базовое копирование**

```bash
# Локальный → удалённый
scp file.txt user@server:/home/user/

# Удалённый → локальный
scp user@server:/var/log/app.log .

# Каталог рекурсивно
scp -r ./site user@server:/var/www/

# Между двумя удалёнными хостами (через локальную машину)
scp -3 user@host1:/data/file user@host2:/backup/
```

### **Полезные флаги**

| Флаг           | Описание                                               |
| -------------- | ------------------------------------------------------ |
| `-P 2222`      | Порт SSH (заглавная P, в отличие от `ssh -p`)          |
| `-i key`       | Файл приватного ключа                                  |
| `-r`           | Рекурсивно                                             |
| `-p`           | Сохранить права и время изменения                      |
| `-C`           | Сжатие                                                 |
| `-l 1000`      | Ограничение скорости, Кбит/с                           |
| `-J jump`      | Через промежуточный хост (ProxyJump)                   |
| `-O`           | Использовать классический протокол SCP вместо SFTP     |
| `-v`           | Подробный вывод                                        |

### **Windows**

```powershell
# OpenSSH встроен в Windows 10/11
scp C:\backup.zip user@server:/backups/

# PuTTY
pscp -P 22 backup.zip user@server:/backups/
```

### **Альтернативы**

```bash
# rsync через SSH — докачка, синхронизация только изменений
rsync -avz --progress ./site/ user@server:/var/www/site/

# sftp
sftp user@server <<< "put backup.zip /backups/"

# tar через ssh — быстро для множества мелких файлов
tar czf - ./data | ssh user@server "tar xzf - -C /backup"
```

## **Безопасность SCP**

### **Рекомендации**

- Использовать актуальный OpenSSH (9.0+), где `scp` работает через SFTP
- Не копировать файлы с недоверенных серверов классическим протоколом (`-O`)
- Аутентификация по ключам, отключение входа по паролю
- Для ограниченных пользователей — `rssh`/`internal-sftp` вместо полного shell
- Проверять host key сервера

## **Сравнение SCP, SFTP и rsync**

| Характеристика      | SCP                 | SFTP                | rsync (через SSH)          |
| ------------------- | ------------------- | ------------------- | -------------------------- |
| **Простота**        | Очень простой       | Средне              | Средне                     |
| **Скорость**        | Высокая             | Высокая             | Высокая, передаёт только изменения |
| **Докачка**         | Нет                 | Да                  | Да                         |
| **Управление файлами** | Нет              | Да                  | Удаление при синхронизации |
| **Интерактивный режим** | Нет             | Да                  | Нет                        |
| **Статус**          | Устарел             | Рекомендуется       | Рекомендуется для синхронизации |
