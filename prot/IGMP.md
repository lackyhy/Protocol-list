**IGMP** (Internet Group Management Protocol) — протокол управления членством в multicast-группах в сетях IPv4. С его помощью хосты сообщают ближайшему маршрутизатору, что хотят получать трафик определённой группы (например, IPTV-канала), а маршрутизатор периодически проверяет, остались ли подписчики. В IPv6 его роль выполняет MLD (часть ICMPv6).

## **Основные характеристики**

| Параметр                    | Описание                                                                 |
| --------------------------- | ------------------------------------------------------------------------ |
| **Уровень OSI**             | Сетевой (Network Layer)                                                  |
| **Инкапсуляция**            | IPv4, номер протокола 2                                                  |
| **TTL**                     | 1 (не выходит за пределы сегмента)                                       |
| **Версии**                  | IGMPv1 (RFC 1112), IGMPv2 (RFC 2236), IGMPv3 (RFC 9776, ранее RFC 3376)  |
| **Назначение**              | Хост ↔ маршрутизатор: управление подпиской на multicast                  |
| **Аналог в IPv6**           | MLD                                                                      |

## **Multicast-адреса IPv4**

Multicast использует диапазон **224.0.0.0/4** (224.0.0.0 – 239.255.255.255).

| Диапазон                  | Назначение                                               |
| ------------------------- | -------------------------------------------------------- |
| `224.0.0.0/24`            | Local Network Control — не маршрутизируются (OSPF, VRRP) |
| `224.0.1.0/24`            | Internetwork Control (NTP 224.0.1.1)                     |
| `232.0.0.0/8`             | Source-Specific Multicast (SSM)                          |
| `233.0.0.0/8`             | GLOP — по номеру AS                                      |
| `239.0.0.0/8`             | Administratively Scoped — частные (аналог 10.0.0.0/8)    |

### **Известные адреса**

| Адрес          | Назначение                       |
| -------------- | -------------------------------- |
| `224.0.0.1`    | Все хосты в сегменте             |
| `224.0.0.2`    | Все маршрутизаторы               |
| `224.0.0.5`/`6` | OSPF                            |
| `224.0.0.9`    | RIPv2                            |
| `224.0.0.10`   | EIGRP                            |
| `224.0.0.13`   | PIM                              |
| `224.0.0.18`   | VRRP                             |
| `224.0.0.22`   | IGMPv3 Reports                   |
| `224.0.0.251`  | mDNS                             |
| `239.255.255.250` | SSDP (UPnP)                   |

### **Отображение в MAC-адрес**

```
MAC multicast = 01:00:5E + младшие 23 бита IP-адреса

239.1.1.1  →  01:00:5E:01:01:01
224.1.1.1  →  01:00:5E:01:01:01   (32 IP-адреса дают один MAC)
```

## **Структура IGMPv2 сообщения**

| Поле                    | Размер (байты) | Описание                                       |
| ----------------------- | -------------- | ---------------------------------------------- |
| **Type**                | 1              | Тип сообщения                                  |
| **Max Response Time**   | 1              | Максимальное время ответа (в десятых секунды)  |
| **Checksum**            | 2              | Контрольная сумма                              |
| **Group Address**       | 4              | Адрес группы (0.0.0.0 для General Query)       |

**Размер:** 8 байт

## **Типы сообщений**

| Type   | Сообщение                    | Версия | Описание                                         |
| ------ | ---------------------------- | ------ | ------------------------------------------------ |
| `0x11` | Membership Query             | v1–v3  | Запрос: «Кто подписан?» (General или Group-Specific) |
| `0x12` | v1 Membership Report         | v1     | Подписка на группу                               |
| `0x16` | v2 Membership Report         | v2     | Подписка на группу                               |
| `0x17` | Leave Group                  | v2     | Выход из группы (на 224.0.0.2)                   |
| `0x22` | v3 Membership Report         | v3     | Подписка с фильтрацией источников                |

## **Версии IGMP**

| Возможность                 | IGMPv1 | IGMPv2 | IGMPv3 |
| --------------------------- | ------ | ------ | ------ |
| **Join (Report)**           | Да     | Да     | Да     |
| **Явный выход (Leave)**     | Нет (по таймауту) | Да | Да  |
| **Group-Specific Query**    | Нет    | Да     | Да     |
| **Выбор Querier**           | Нет    | Да (наименьший IP) | Да |
| **Фильтр источников (SSM)** | Нет    | Нет    | Да (INCLUDE/EXCLUDE) |

## **Процесс работы**

```
Хост                                Маршрутизатор (Querier)
  |                                          |
  |-- Report (join 239.1.1.1) ------------->|  Хост хочет канал
  |                                          |  Роутер начинает пересылать поток
  |<========= multicast 239.1.1.1 ==========|
  |                                          |
  |<-- General Query (каждые 125 с) --------|  «Кто ещё смотрит?»
  |-- Report (239.1.1.1) ------------------>|
  |                                          |
  |-- Leave (239.1.1.1) ------------------->|  Хост переключил канал
  |<-- Group-Specific Query (239.1.1.1) ----|  «Остался кто-нибудь?»
  |        (нет ответа)                      |
  |                                    Поток остановлен
```

### **Таймеры (IGMPv2)**

| Таймер                          | Значение по умолчанию |
| ------------------------------- | --------------------- |
| Query Interval                  | 125 с                 |
| Query Response Interval         | 10 с                  |
| Group Membership Interval       | 260 с                 |
| Last Member Query Interval      | 1 с                   |

## **IGMP Snooping**

Без snooping коммутатор рассылает multicast на **все** порты VLAN как broadcast. С IGMP Snooping коммутатор «подслушивает» Report/Leave и отправляет поток только на порты подписчиков.

| Функция                | Описание                                                 |
| ---------------------- | -------------------------------------------------------- |
| **IGMP Snooping**      | Построение таблицы «группа → порты»                      |
| **IGMP Querier**       | Коммутатор сам отправляет Query, если роутера нет        |
| **Fast Leave**         | Мгновенное отключение порта при Leave (если хост один)   |
| **MVR**                | Multicast VLAN Registration — один multicast VLAN для многих клиентских |

## **Связь с маршрутизацией multicast**

IGMP работает только между хостом и первым маршрутизатором. Между маршрутизаторами multicast-деревья строит **PIM** (Protocol Independent Multicast):

| Режим          | Описание                                                  |
| -------------- | --------------------------------------------------------- |
| **PIM-DM**     | Dense Mode — flood and prune, для плотных сетей           |
| **PIM-SM**     | Sparse Mode — через точку встречи (RP)                    |
| **PIM-SSM**    | Source-Specific — сразу от источника, требует IGMPv3      |

## **Примеры использования**

### **Просмотр групп на Linux**

```bash
ip maddr show
netstat -g
cat /proc/net/igmp
```

### **Подписка на группу и приём потока**

```bash
# Принять UDP-поток IPTV
ffplay udp://@239.1.1.1:1234

# socat — подписаться на группу
socat UDP4-RECVFROM:1234,ip-add-membership=239.1.1.1:eth0 -
```

### **Включение IGMPv3 / v2 на Linux**

```bash
sysctl -w net.ipv4.conf.eth0.force_igmp_version=2
```

### **Cisco IOS**

```
ip multicast-routing
interface GigabitEthernet0/1
 ip pim sparse-mode
 ip igmp version 3

! Коммутатор
ip igmp snooping
ip igmp snooping vlan 10 querier

show ip igmp groups
show ip igmp snooping groups
```

### **Wireshark**

```
igmp
igmp.type == 0x22
```

## **Применение**

1. **IPTV** — каждый канал = multicast-группа
2. **Биржевые котировки** — рассылка данных многим получателям
3. **Видеонаблюдение** — потоки с камер
4. **Обнаружение сервисов** — mDNS, SSDP
5. **Развёртывание ОС** — массовая установка образов (multicast imaging)

## **Безопасность IGMP**

### **Угрозы**

1. **Подписка на чужие группы** — доступ к платным IPTV-каналам
2. **Flood Report-сообщений** — перегрузка таблиц коммутатора/роутера
3. **Поддельный Querier** — нарушение работы multicast

### **Защита**

- **IGMP Filtering** — профили разрешённых групп на портах
- **Ограничение количества групп** на порт (`ip igmp max-groups`)
- Фильтрация IGMP Query с клиентских портов
- IGMPv3 + SSM — получать только от доверенных источников

## **Сравнение IGMP и MLD**

| Характеристика | IGMP (IPv4)            | MLD (IPv6)                  |
| -------------- | ---------------------- | --------------------------- |
| **Транспорт**  | Протокол IP 2          | ICMPv6                      |
| **Версии**     | v1, v2, v3             | v1 (≈IGMPv2), v2 (≈IGMPv3)  |
| **Snooping**   | IGMP Snooping          | MLD Snooping                |
