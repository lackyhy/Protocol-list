**NAT** (Network Address Translation) — механизм преобразования IP-адресов (и часто портов) в заголовках пакетов при прохождении через маршрутизатор. NAT позволяет множеству устройств с частными адресами выходить в интернет через один или несколько публичных адресов. Формально NAT — не протокол, а функция маршрутизатора, но без него невозможно понять работу современных сетей.

## **Основные характеристики**

| Параметр                    | Описание                                                                 |
| --------------------------- | ------------------------------------------------------------------------ |
| **Уровень OSI**             | Сетевой (NAT) и транспортный (PAT — порты)                               |
| **Стандарты**               | RFC 3022 (Traditional NAT), RFC 4787 и RFC 5382 (поведение для UDP и TCP) |
| **Назначение**              | Экономия IPv4-адресов, скрытие внутренней сети                           |
| **Состояние**               | Хранит таблицу трансляций (stateful)                                     |
| **Связанные технологии**    | CGNAT, NAT64, STUN/TURN, UPnP/NAT-PMP/PCP                                |

## **Частные адреса (RFC 1918)**

| Диапазон                       | Маска  | Количество адресов |
| ------------------------------ | ------ | ------------------ |
| `10.0.0.0 – 10.255.255.255`    | /8     | 16 777 216         |
| `172.16.0.0 – 172.31.255.255`  | /12    | 1 048 576          |
| `192.168.0.0 – 192.168.255.255` | /16   | 65 536             |
| `100.64.0.0 – 100.127.255.255` | /10    | Shared Address Space для CGNAT (RFC 6598) |

## **Терминология**

| Термин              | Описание                                               | Пример         |
| ------------------- | ------------------------------------------------------ | -------------- |
| **Inside Local**    | Адрес хоста внутри сети                                | 192.168.1.10   |
| **Inside Global**   | Адрес, под которым хост виден снаружи                  | 203.0.113.5    |
| **Outside Local**   | Адрес внешнего хоста, как его видят изнутри            | 8.8.8.8        |
| **Outside Global**  | Реальный адрес внешнего хоста                          | 8.8.8.8        |

## **Типы NAT**

| Тип                      | Описание                                                         |
| ------------------------ | ---------------------------------------------------------------- |
| **Static NAT (1:1)**     | Один внутренний адрес ↔ один публичный, постоянно                |
| **Dynamic NAT**          | Внутренние адреса получают публичные из пула, пока есть свободные |
| **PAT / NAPT / Masquerade** | Много внутренних → один публичный, различаются по портам (самый распространённый) |
| **Port Forwarding (DNAT)** | Входящие соединения на порт публичного адреса → внутренний хост |
| **SNAT**                 | Подмена адреса источника (исходящий трафик)                      |
| **DNAT**                 | Подмена адреса назначения (входящий трафик, балансировка)        |
| **Twice NAT**            | Подмена и источника, и назначения (пересекающиеся сети)          |
| **CGNAT (NAT444)**       | NAT на стороне провайдера, клиенты за двойным NAT                |
| **NAT64**                | Трансляция IPv6 ↔ IPv4                                           |

## **Как работает PAT**

```
Внутренняя сеть                 Роутер NAT                        Интернет
192.168.1.10:51000  --->  203.0.113.5:40001  --->  93.184.216.34:443
192.168.1.11:51000  --->  203.0.113.5:40002  --->  93.184.216.34:443
192.168.1.12:62000  --->  203.0.113.5:40003  --->  142.250.74.46:443
```

### **Таблица трансляций**

| Протокол | Inside Local         | Inside Global        | Outside               |
| -------- | -------------------- | -------------------- | --------------------- |
| TCP      | 192.168.1.10:51000   | 203.0.113.5:40001    | 93.184.216.34:443     |
| TCP      | 192.168.1.11:51000   | 203.0.113.5:40002    | 93.184.216.34:443     |
| UDP      | 192.168.1.12:62000   | 203.0.113.5:40003    | 142.250.74.46:443     |

Ответный пакет на `203.0.113.5:40002` по таблице возвращается на `192.168.1.11:51000`.

## **Типы поведения NAT (важно для P2P)**

### **Классификация RFC 3489 (классическая)**

| Тип                          | Кто может отправить пакет на открытый маппинг                 |
| ---------------------------- | ------------------------------------------------------------- |
| **Full Cone**                | Любой внешний хост                                            |
| **Restricted Cone**          | Только хост, которому уже отправляли (любой порт)             |
| **Port Restricted Cone**     | Только тот хост и порт, которому отправляли                   |
| **Symmetric**                | Для каждого получателя — свой внешний порт; P2P почти невозможен |

### **Классификация RFC 4787 (современная)**

| Параметр              | Варианты                                                        |
| --------------------- | --------------------------------------------------------------- |
| **Mapping**           | Endpoint-Independent / Address-Dependent / Address and Port-Dependent |
| **Filtering**         | Endpoint-Independent / Address-Dependent / Address and Port-Dependent |

## **Проблемы NAT**

1. **Нарушение сквозной связности** — внешний хост не может инициировать соединение внутрь
2. **P2P и VoIP** — нужны STUN/TURN/ICE, UPnP
3. **Протоколы с адресами в данных** — FTP (активный режим), SIP, H.323 требуют ALG
4. **IPsec** — AH несовместим с NAT, ESP требует NAT-T (UDP 4500)
5. **Логирование** — за одним IP много пользователей
6. **CGNAT** — нельзя пробросить порт, проблемы с играми и серверами
7. **Hairpinning** — доступ к своему серверу по публичному адресу изнутри

## **Механизмы обхода NAT**

| Механизм           | Описание                                                    |
| ------------------ | ----------------------------------------------------------- |
| **Port Forwarding** | Ручной проброс порта                                       |
| **UPnP IGD**       | Приложение само открывает порт на роутере                   |
| **NAT-PMP / PCP**  | Протоколы проброса портов (Apple, RFC 6887)                 |
| **STUN**           | Узнать свой внешний адрес и тип NAT                         |
| **TURN**           | Ретрансляция через сервер, если прямое соединение невозможно |
| **ICE**            | Перебор кандидатов (используется в WebRTC)                  |
| **UDP Hole Punching** | Одновременная отправка пакетов двумя сторонами           |
| **NAT-T**          | Инкапсуляция IPsec ESP в UDP 4500                           |
| **ALG**            | Маршрутизатор правит адреса внутри FTP, SIP и т.п.          |

## **Примеры конфигурации**

### **Linux (iptables)**

```bash
# Включить пересылку
sysctl -w net.ipv4.ip_forward=1

# PAT (masquerade) для выхода в интернет через eth0
iptables -t nat -A POSTROUTING -s 192.168.1.0/24 -o eth0 -j MASQUERADE

# SNAT на фиксированный адрес
iptables -t nat -A POSTROUTING -s 192.168.1.0/24 -o eth0 -j SNAT --to-source 203.0.113.5

# Проброс порта 8080 → внутренний веб-сервер
iptables -t nat -A PREROUTING -i eth0 -p tcp --dport 8080 -j DNAT --to-destination 192.168.1.20:80
iptables -A FORWARD -p tcp -d 192.168.1.20 --dport 80 -j ACCEPT
```

### **Linux (nftables)**

```
table ip nat {
    chain postrouting {
        type nat hook postrouting priority 100;
        oifname "eth0" masquerade
    }
    chain prerouting {
        type nat hook prerouting priority -100;
        iifname "eth0" tcp dport 8080 dnat to 192.168.1.20:80
    }
}
```

### **Просмотр таблицы трансляций (Linux)**

```bash
conntrack -L
conntrack -L -p tcp --dport 443
cat /proc/net/nf_conntrack
```

### **Cisco IOS — PAT**

```
interface GigabitEthernet0/0
 ip nat outside
interface GigabitEthernet0/1
 ip nat inside

access-list 1 permit 192.168.1.0 0.0.0.255
ip nat inside source list 1 interface GigabitEthernet0/0 overload

! Static NAT / проброс порта
ip nat inside source static tcp 192.168.1.20 80 203.0.113.5 8080

show ip nat translations
show ip nat statistics
```

## **NAT и безопасность**

- NAT **не является файрволом**, хотя и блокирует незапрошенные входящие соединения как побочный эффект
- Без stateful-файрвола проброшенные порты открыты всему интернету
- UPnP может открыть порты без ведома администратора (особенно на заражённых устройствах)
- В IPv6 NAT обычно не используется — безопасность обеспечивает файрвол

## **NAT в IPv6**

| Механизм     | Описание                                                     |
| ------------ | ------------------------------------------------------------ |
| **NAT64**    | IPv6-клиенты обращаются к IPv4-серверам через префикс `64:ff9b::/96` |
| **NPTv6**    | Трансляция префикса 1:1 без портов (RFC 6296)                |
| **NAT66**    | Классический NAT для IPv6 — не рекомендуется                 |
