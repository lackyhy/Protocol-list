**NetBIOS** (Network Basic Input/Output System) — программный интерфейс 1980-х годов для связи приложений в локальной сети, созданный IBM и Sytek. Сам по себе NetBIOS — это API, а не протокол; в сетях TCP/IP он работает через **NetBT** (NetBIOS over TCP/IP), состоящий из трёх служб: именования, датаграмм и сеансов. NetBIOS долго был основой сетей Windows («Сетевое окружение», общие папки), но сейчас устарел и его рекомендуют отключать.

## **Основные характеристики**

| Параметр                    | Описание                                                                 |
| --------------------------- | ------------------------------------------------------------------------ |
| **Уровень OSI**             | Сеансовый (Session Layer)                                                |
| **Стандарт NetBT**          | RFC 1001, RFC 1002 (1987)                                                |
| **Порты**                   | UDP 137 (имена), UDP 138 (датаграммы), TCP 139 (сеансы)                  |
| **Длина имени**             | 15 символов + 1 байт суффикса типа                                       |
| **Разрешение имён**         | Broadcast, WINS, файл LMHOSTS                                            |
| **Статус**                  | Устарел, вытеснен DNS и прямым SMB over TCP (порт 445)                    |

## **Три службы NetBIOS over TCP/IP**

| Служба                     | Порт     | Назначение                                      |
| -------------------------- | -------- | ----------------------------------------------- |
| **Name Service (NBNS/WINS)** | UDP 137 | Регистрация и разрешение имён NetBIOS           |
| **Datagram Service**       | UDP 138  | Передача без установления соединения (broadcast, анонсы) |
| **Session Service**        | TCP 139  | Надёжный сеанс для передачи данных (SMB)         |

## **Имена NetBIOS**

Имя — 16 байт: 15 символов имени + последний байт **суффикс**, указывающий тип ресурса.

| Суффикс (hex) | Тип                  | Описание                               |
| ------------- | -------------------- | -------------------------------------- |
| `00`          | Workstation          | Имя компьютера                         |
| `03`          | Messenger            | Служба сообщений                       |
| `20`          | File Server          | Служба общего доступа к файлам         |
| `1B`          | Domain Master Browser | Главный обозреватель домена            |
| `1C`          | Domain Controllers   | Группа контроллеров домена             |
| `1D`          | Master Browser       | Главный обозреватель сегмента          |
| `1E`          | Browser Elections    | Выборы обозревателя                    |

## **Режимы разрешения имён (Node Types)**

| Тип      | Название   | Способ                                             |
| -------- | ---------- | -------------------------------------------------- |
| **B-node** | Broadcast | Только широковещательные запросы в сегменте        |
| **P-node** | Peer      | Только через сервер WINS                           |
| **M-node** | Mixed     | Сначала broadcast, затем WINS                      |
| **H-node** | Hybrid    | Сначала WINS, затем broadcast (по умолчанию в AD)  |

## **WINS**

**WINS** (Windows Internet Name Service) — сервер, централизованно хранящий таблицу «имя NetBIOS → IP», аналог DNS для имён NetBIOS. Позволял разрешать имена между сегментами, где broadcast не проходит. В современных сетях заменён DNS.

## **Как работает (общая схема)**

```
1. Регистрация имени:
   Компьютер при старте объявляет свои имена (broadcast или WINS)
   Если имя занято — конфликт, компьютер не регистрирует его

2. Разрешение имени:
   "Где FILESERVER<20>?" → ответ: 10.0.0.20

3. Сеанс:
   TCP-соединение на порт 139, поверх которого работает SMB
```

## **NetBIOS и SMB**

Исторически SMB работал поверх NetBIOS (порт 139). Начиная с Windows 2000, SMB умеет работать **напрямую поверх TCP на порту 445** без NetBIOS. Современные сети используют только порт 445, а NetBIOS (137–139) остаётся лишь для совместимости со старыми системами. Подробнее — в [SMB/CIFS](SMB-CIFS.md).

| Вариант           | Порты        | Нужен NetBIOS |
| ----------------- | ------------ | ------------- |
| **SMB over NetBIOS** | TCP 139 + UDP 137/138 | Да   |
| **SMB over TCP (direct hosting)** | TCP 445 | Нет |

## **Примеры использования**

### **Windows**

```
nbtstat -n                 # локальные зарегистрированные имена
nbtstat -A 10.0.0.20       # имена удалённого хоста по IP
nbtstat -a FILESERVER      # имена по имени
nbtstat -c                 # кэш имён NetBIOS
nbtstat -R                 # очистить и перезагрузить кэш из LMHOSTS
```

### **Linux (Samba)**

```bash
nmblookup FILESERVER       # разрешить имя NetBIOS в IP
nmblookup -A 10.0.0.20     # имена хоста по IP
nmblookup -S WORKGROUP     # обозреватели рабочей группы
```

### **Проверка открытых портов**

```bash
nmap -sU -p 137 --script nbstat 10.0.0.0/24
nmap -p 139,445 10.0.0.20
```

### **Wireshark**

```
nbns           # Name Service
nbdgm          # Datagram Service
nbss           # Session Service
udp.port == 137 || tcp.port == 139
```

## **Безопасность**

### **Почему NetBIOS рекомендуют отключать**

1. **Утечка информации** — служба имён раскрывает имена компьютеров, имя домена/рабочей группы, иногда имя вошедшего пользователя и MAC-адрес
2. **NBT-NS poisoning** — broadcast-разрешение имён позволяет постороннему устройству в сегменте ответить за несуществующее имя (аналогично [LLMNR](LLMNR.md)); это используется для перехвата попыток аутентификации
3. **Устаревшая аутентификация** — связка со старыми версиями SMB и NTLM
4. **Усиление DDoS** — открытый в интернет UDP 137 использовался для amplification-атак
5. **Поверхность атаки** — лишние открытые порты на периметре

### **Рекомендации**

- Блокировать порты 137–139 на периметре сети (они никогда не должны быть доступны из интернета)
- Отключить NetBIOS over TCP/IP там, где не нужна совместимость со старыми системами:

```powershell
# Для всех адаптеров с IP
Get-CimInstance Win32_NetworkAdapterConfiguration -Filter "IPEnabled=true" |
    Invoke-CimMethod -MethodName SetTcpipNetbios -Arguments @{TcpipNetbiosOptions = 2}
# 0 = по умолчанию (DHCP), 1 = включить, 2 = отключить
```

- Или через DHCP: опция Microsoft **001** (Disable NetBIOS over TCP/IP)
- Отключить вместе с [LLMNR](LLMNR.md) и ограничить mDNS, чтобы убрать все broadcast/multicast-механизмы разрешения имён
- Включить **SMB Signing** и отказаться от NTLM в пользу Kerberos
- Выводить из эксплуатации WINS, переходить на DNS

## **Сравнение способов разрешения имён в сетях Windows**

| Характеристика      | NetBIOS-NS (NBT-NS)  | LLMNR                 | DNS                     |
| ------------------- | -------------------- | --------------------- | ----------------------- |
| **Порт**            | UDP 137              | UDP 5355              | UDP/TCP 53              |
| **Рассылка**        | Broadcast / WINS     | Multicast             | Unicast к серверу       |
| **Границы**         | Сегмент (или WINS)   | Сегмент               | Вся сеть / интернет     |
| **Длина имён**      | 15 символов          | Одно слово            | Полные доменные имена   |
| **IPv6**            | Нет                  | Да                    | Да                      |
| **Статус**          | Устарел              | Устаревает            | Основной                |
