**LACP** (Link Aggregation Control Protocol) — протокол динамического объединения нескольких физических каналов Ethernet в один логический (агрегированный) канал. Агрегирование увеличивает пропускную способность и даёт отказоустойчивость: если один кабель отказывает, трафик продолжает идти по остальным. Логический канал называют по-разному: **EtherChannel** / **Port-Channel** (Cisco), **LAG**, **bond** (Linux), **team** (Windows).

## **Основные характеристики**

| Параметр                    | Описание                                                                 |
| --------------------------- | ------------------------------------------------------------------------ |
| **Уровень OSI**             | Канальный (Data Link Layer)                                              |
| **Стандарт**                | IEEE 802.3ad (2000), сейчас IEEE 802.1AX                                 |
| **Сообщения**               | LACPDU (Slow Protocols, EtherType `0x8809`, subtype 1)                   |
| **Адрес**                   | `01:80:C2:00:00:02`                                                      |
| **Количество каналов**      | До 8 активных + до 8 резервных (зависит от оборудования)                 |
| **Интервал LACPDU**         | Slow — 30 с, Fast — 1 с                                                  |
| **Альтернатива**            | PAgP (Cisco, проприетарный), статическое агрегирование                   |

## **Зачем нужно агрегирование**

1. **Пропускная способность** — 4 × 1 Гбит/с = до 4 Гбит/с суммарно
2. **Отказоустойчивость** — обрыв одного кабеля не разрывает связь
3. **STP видит один канал** — нет заблокированных резервных портов
4. **Экономия** — не нужно сразу покупать 10G оборудование

## **Режимы LACP**

| Режим       | Описание                                                  |
| ----------- | --------------------------------------------------------- |
| **Active**  | Порт сам отправляет LACPDU и инициирует согласование      |
| **Passive** | Порт только отвечает на LACPDU                            |

| Сторона A  | Сторона B  | Результат                 |
| ---------- | ---------- | ------------------------- |
| Active     | Active     | Канал создаётся           |
| Active     | Passive    | Канал создаётся           |
| Passive    | Passive    | **Канал не создаётся**    |
| On (static) | On (static) | Канал без LACP (без проверок) |
| On         | Active     | Не работает               |

## **Содержимое LACPDU**

| Поле                    | Описание                                                    |
| ----------------------- | ----------------------------------------------------------- |
| **System Priority**     | Приоритет системы (по умолчанию 32768)                      |
| **System ID**           | MAC-адрес устройства                                        |
| **Key**                 | Ключ агрегации — порты с одинаковым ключом могут объединяться |
| **Port Priority**       | Приоритет порта (какие порты активны, если их больше 8)     |
| **Port Number**         | Номер порта                                                 |
| **State**               | Флаги состояния                                             |

### **Флаги состояния (Actor/Partner State)**

| Бит | Флаг               | Значение                                          |
| --- | ------------------ | ------------------------------------------------- |
| 0   | **LACP_Activity**  | 1 = Active, 0 = Passive                           |
| 1   | **LACP_Timeout**   | 1 = Fast (1 с), 0 = Slow (30 с)                   |
| 2   | **Aggregation**    | Порт может агрегироваться                         |
| 3   | **Synchronization** | Порт в правильной группе                         |
| 4   | **Collecting**     | Принимает кадры                                   |
| 5   | **Distributing**   | Отправляет кадры                                  |
| 6   | **Defaulted**      | Нет данных от партнёра                            |
| 7   | **Expired**        | Данные партнёра устарели                          |

## **Требования к портам**

Все порты в группе должны совпадать по:
- Скорости и дуплексу
- Режиму (access/trunk), VLAN и native VLAN
- Списку разрешённых VLAN на транке
- Настройкам STP

## **Балансировка нагрузки**

LACP **не делит один поток** между каналами. Каждый поток (сессия) идёт по одному физическому каналу, выбранному по хэшу:

| Алгоритм хэша       | Учитывает                                    |
| ------------------- | -------------------------------------------- |
| **src-mac / dst-mac** | MAC-адреса                                 |
| **src-dst-ip**      | IP-адреса источника и назначения             |
| **src-dst-port / layer3+4** | IP + порты TCP/UDP (лучшее распределение) |

```
Поток 1 (A → B:443)  ──hash──> канал 1
Поток 2 (A → C:443)  ──hash──> канал 3
Поток 3 (D → B:22)   ──hash──> канал 2

Один большой поток копирования файла = максимум скорость одного канала (1 Гбит/с)
```

## **MLAG / MC-LAG**

Обычный LAG связывает два устройства. **MLAG** (Multi-Chassis LAG) позволяет сделать агрегацию с двумя разными коммутаторами — сервер подключается к двум коммутаторам, и при отказе одного продолжает работать.

| Реализация         | Вендор         |
| ------------------ | -------------- |
| **vPC**            | Cisco Nexus    |
| **StackWise / VSS** | Cisco Catalyst |
| **MLAG**           | Arista, NVIDIA |
| **MC-LAG**         | Juniper        |
| **EVPN Multihoming (ESI-LAG)** | Стандартный способ в дата-центрах |

## **Примеры конфигурации**

### **Cisco IOS**

```
interface range GigabitEthernet0/1 - 2
 channel-group 1 mode active
 lacp rate fast

interface Port-channel1
 switchport mode trunk
 switchport trunk allowed vlan 10,20

port-channel load-balance src-dst-ip
```

```
show etherchannel summary
show lacp neighbor
show interfaces port-channel 1
```

### **Linux (iproute2)**

```bash
ip link add bond0 type bond mode 802.3ad lacp_rate fast xmit_hash_policy layer3+4
ip link set eth0 down && ip link set eth0 master bond0
ip link set eth1 down && ip link set eth1 master bond0
ip link set bond0 up
ip addr add 192.168.1.10/24 dev bond0

cat /proc/net/bonding/bond0
```

### **Linux (netplan)**

```yaml
network:
  version: 2
  ethernets:
    eth0: {}
    eth1: {}
  bonds:
    bond0:
      interfaces: [eth0, eth1]
      addresses: [192.168.1.10/24]
      parameters:
        mode: 802.3ad
        lacp-rate: fast
        transmit-hash-policy: layer3+4
```

### **Windows Server**

```powershell
New-NetLbfoTeam -Name "Team1" -TeamMembers "Ethernet1","Ethernet2" `
    -TeamingMode Lacp -LoadBalancingAlgorithm Dynamic
```

### **MikroTik RouterOS**

```
/interface bonding add name=bond1 mode=802.3ad slaves=ether1,ether2 \
    transmit-hash-policy=layer-3-and-4 lacp-rate=1sec
```

## **Режимы Linux bonding**

| Режим | Название         | Нужна поддержка коммутатора | Описание                          |
| ----- | ---------------- | --------------------------- | --------------------------------- |
| 0     | balance-rr       | Статический LAG             | Пакеты по очереди                 |
| 1     | active-backup    | Нет                         | Один активный, остальные резерв   |
| 2     | balance-xor      | Статический LAG             | По хэшу                           |
| 3     | broadcast        | Статический LAG             | Копия на все каналы               |
| 4     | **802.3ad**      | **LACP**                    | Стандартная динамическая агрегация |
| 5     | balance-tlb      | Нет                         | Балансировка отправки             |
| 6     | balance-alb      | Нет                         | Балансировка отправки и приёма    |

## **Диагностика проблем**

| Проблема                          | Причина                                         |
| --------------------------------- | ----------------------------------------------- |
| Порт в состоянии `suspended` / `I` | Нет LACPDU от партнёра, несовпадение настроек  |
| Канал не поднимается              | Passive + Passive, LACP + static                |
| Неравномерная загрузка            | Неудачный алгоритм хэша (мало потоков)          |
| Петля при ошибке кабеля           | Статический LAG без LACP не проверяет соседа    |

## **Сравнение LACP, PAgP и статического LAG**

| Характеристика     | LACP                    | PAgP                | Static (mode on)       |
| ------------------ | ----------------------- | ------------------- | ---------------------- |
| **Стандарт**       | IEEE 802.1AX            | Cisco               | —                      |
| **Режимы**         | Active / Passive        | Desirable / Auto    | On                     |
| **Проверка соседа** | Да                     | Да                  | Нет                    |
| **Обнаружение ошибок кабелей** | Да          | Да                  | Нет                    |
| **Совместимость**  | Все вендоры             | Только Cisco        | Все                    |
