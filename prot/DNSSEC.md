**DNSSEC** (Domain Name System Security Extensions) — набор расширений DNS, который добавляет к записям цифровые подписи. С DNSSEC резолвер может проверить, что ответ действительно пришёл от владельца зоны и не был подменён по пути. DNSSEC защищает **целостность и подлинность** данных DNS, но **не шифрует** запросы — для конфиденциальности используются DoH и DoT.

## **Основные характеристики**

| Параметр                    | Описание                                                                 |
| --------------------------- | ------------------------------------------------------------------------ |
| **Уровень OSI**             | Прикладной (расширение DNS)                                              |
| **Стандарты**               | RFC 4033, 4034, 4035 (основные), RFC 5155 (NSEC3), RFC 8624 (алгоритмы)  |
| **Транспорт**               | Как DNS: UDP/TCP 53, требует EDNS0 (большие ответы)                      |
| **Криптография**            | Асимметричная: RSA, ECDSA P-256, Ed25519                                 |
| **Защищает от**             | Подмены ответов, отравления кэша (Kaminsky attack)                      |
| **Не защищает от**          | Прослушивания, DDoS, компрометации регистратора                          |
| **Корень подписан**         | С 2010 года                                                              |

## **Проблема, которую решает DNSSEC**

Обычный DNS не проверяет подлинность ответов. Злоумышленник может отправить поддельный ответ раньше настоящего (**DNS spoofing**) или отравить кэш резолвера (**cache poisoning**), и пользователи попадут на фишинговый сайт.

```
Без DNSSEC:  bank.com → 6.6.6.6 (подделка)   — резолвер верит
С DNSSEC:    bank.com → 6.6.6.6 + нет верной подписи — ответ отвергнут (SERVFAIL)
```

## **Новые типы записей**

| Запись       | Описание                                                            |
| ------------ | ------------------------------------------------------------------- |
| **RRSIG**    | Подпись набора записей (RRset)                                      |
| **DNSKEY**   | Публичные ключи зоны                                                |
| **DS**       | Delegation Signer — хэш ключа дочерней зоны, хранится в родительской |
| **NSEC**     | Доказательство отсутствия записи (следующее имя в зоне)             |
| **NSEC3**    | То же, но с хэшированными именами (защита от перебора зоны)         |
| **NSEC3PARAM** | Параметры NSEC3                                                   |
| **CDS / CDNSKEY** | Автоматическое обновление DS у родителя (RFC 7344, 8078)       |

## **Ключи**

| Ключ                           | Флаг   | Назначение                                     |
| ------------------------------ | ------ | ---------------------------------------------- |
| **KSK** (Key Signing Key)      | 257    | Подписывает только набор DNSKEY; его хэш (DS) публикуется у родителя |
| **ZSK** (Zone Signing Key)     | 256    | Подписывает все остальные записи зоны          |
| **CSK** (Combined Signing Key) | 257    | Один ключ в обеих ролях (упрощённая схема)     |

Разделение KSK и ZSK позволяет часто менять ZSK, не трогая родительскую зону.

## **Цепочка доверия**

```
  . (корень)        DNSKEY (KSK корня) ← Trust Anchor встроен в резолвер
      │             DS для com.
      ▼
  com.              DNSKEY (KSK, ZSK) — хэш KSK совпадает с DS в корне
      │             DS для example.com.
      ▼
  example.com.      DNSKEY (KSK, ZSK) — хэш KSK совпадает с DS в com.
      │
      ▼
  www.example.com. A 93.184.216.34
                   RRSIG (подписано ZSK example.com)
```

Резолвер проверяет каждое звено от корня до записи. Если звено разорвано — ответ считается поддельным.

## **Процесс проверки (валидации)**

```
1. Резолвер запрашивает www.example.com A с флагом DO (DNSSEC OK)
2. Получает A + RRSIG
3. Запрашивает DNSKEY example.com, проверяет RRSIG записи A ключом ZSK
4. Проверяет RRSIG набора DNSKEY ключом KSK
5. Запрашивает DS example.com у com., сравнивает хэш с KSK
6. Повторяет для com. до корня, где ключ = Trust Anchor
7. Всё совпало → флаг AD (Authenticated Data) в ответе клиенту
```

### **Результаты валидации**

| Статус          | Описание                                     | Ответ клиенту   |
| --------------- | -------------------------------------------- | --------------- |
| **Secure**      | Цепочка проверена                            | Данные + AD     |
| **Insecure**    | Зона не подписана (нет DS у родителя)        | Данные без AD   |
| **Bogus**       | Подпись неверна или истекла                  | **SERVFAIL**    |
| **Indeterminate** | Не удалось определить                      | SERVFAIL        |

## **Алгоритмы (RFC 8624)**

| Номер | Алгоритм                 | Статус                         |
| ----- | ------------------------ | ------------------------------ |
| 5     | RSASHA1                  | Не использовать для подписи    |
| 8     | RSASHA256                | Допустимо, широко используется |
| 10    | RSASHA512                | Не рекомендуется               |
| 13    | ECDSAP256SHA256          | **Рекомендуется**              |
| 14    | ECDSAP384SHA384          | Допустимо                      |
| 15    | ED25519                  | Рекомендуется                  |

## **Примеры использования**

### **Проверка подписи домена**

```bash
dig +dnssec example.com A
dig example.com DNSKEY +multi
dig example.com DS @a.gtld-servers.net

# Цепочка доверия
delv example.com A
drill -S example.com
dig +trace +dnssec example.com

# Флаг AD в ответе — валидация прошла
dig @1.1.1.1 example.com +dnssec | grep flags
```

### **Проверка намеренно сломанного домена**

```bash
dig @1.1.1.1 dnssec-failed.org      # SERVFAIL
dig @1.1.1.1 dnssec-failed.org +cd  # +cd отключает проверку → ответ есть
```

### **Подписание зоны в BIND 9**

```
// named.conf
dnssec-policy "default";      // автоматическое управление ключами (CSK, ECDSA P-256)

zone "example.com" {
    type primary;
    file "example.com.zone";
    dnssec-policy default;
    inline-signing yes;
};
```

```bash
rndc dnssec -status example.com
# Получить DS для передачи регистратору
dnssec-dsfromkey Kexample.com.+013+12345.key
```

### **PowerDNS**

```bash
pdnsutil secure-zone example.com
pdnsutil show-zone example.com     # покажет DS-записи
pdnsutil rectify-zone example.com
```

### **Включение валидации в Unbound**

```
server:
    auto-trust-anchor-file: "/var/lib/unbound/root.key"
    val-log-level: 2
```

## **Операционные риски**

| Проблема                          | Последствие                                     |
| --------------------------------- | ----------------------------------------------- |
| **Истёкшие подписи RRSIG**        | Домен недоступен для валидирующих резолверов    |
| **Ошибка смены KSK**              | DS не совпадает с ключом — домен «пропадает»    |
| **Смена DNS-хостинга без переноса DS** | Сломанная цепочка                          |
| **Большие ответы**                | Фрагментация UDP, переход на TCP, проблемы с файрволами |
| **Amplification-атаки**           | Ответы DNSSEC большие — используются в DDoS     |
| **Перебор зоны (zone walking)**   | NSEC раскрывает все имена; решение — NSEC3 или онлайн-подпись |

## **Связанные технологии**

| Технология   | Описание                                                      |
| ------------ | ------------------------------------------------------------- |
| **DANE / TLSA** | Публикация отпечатков TLS-сертификатов в DNS (защищено DNSSEC) — используется в почте (SMTP) |
| **SSHFP**    | Отпечатки SSH-ключей хоста в DNS                              |
| **CAA**      | Какие центры сертификации могут выпускать сертификаты домена  |

## **Сравнение DNSSEC и шифрования DNS**

| Характеристика      | DNSSEC                       | DoT / DoH                      |
| ------------------- | ---------------------------- | ------------------------------ |
| **Что защищает**    | Подлинность и целостность данных | Конфиденциальность канала  |
| **Где работает**    | От зоны до резолвера (end-to-end по данным) | Клиент ↔ резолвер    |
| **Шифрование**      | Нет                          | Да                             |
| **Защита от подмены резолвером** | Да (если клиент валидирует) | Нет               |
| **Вместе**          | Дополняют друг друга         |                                |
