**Kerberos** — сетевой протокол аутентификации, основанный на билетах (tickets) и доверенной третьей стороне. Пароль пользователя не передаётся по сети: клиент один раз проходит аутентификацию и получает билет, с которым затем входит в разные сервисы без повторного ввода пароля (Single Sign-On). Kerberos — основной протокол аутентификации в Active Directory.

## **Основные характеристики**

| Параметр                    | Описание                                                                 |
| --------------------------- | ------------------------------------------------------------------------ |
| **Уровень OSI**             | Прикладной (Application Layer)                                           |
| **Транспорт**               | UDP и TCP (TCP для больших сообщений)                                    |
| **Порты**                   | 88 (KDC), 464 (смена пароля, kpasswd), 749 (администрирование)           |
| **Версия**                  | Kerberos 5 (RFC 4120)                                                    |
| **Разработчик**             | MIT (проект Athena), 1980-е                                              |
| **Криптография**            | Симметричная (AES), опционально PKINIT (сертификаты)                     |
| **Требование**              | Синхронизация времени (по умолчанию расхождение не более 5 минут)        |
| **Реализации**              | Active Directory, MIT Kerberos, Heimdal, FreeIPA                         |

## **Основные понятия**

| Понятие                | Описание                                                          |
| ---------------------- | ----------------------------------------------------------------- |
| **Realm**              | Область администрирования, обычно домен заглавными буквами: `EXAMPLE.COM` |
| **Principal**          | Участник: пользователь `alice@EXAMPLE.COM` или сервис `HTTP/web.example.com@EXAMPLE.COM` |
| **KDC**                | Key Distribution Center — центр распределения ключей (в AD — контроллер домена) |
| **AS**                 | Authentication Service — часть KDC, выдаёт TGT                   |
| **TGS**                | Ticket Granting Service — часть KDC, выдаёт билеты на сервисы    |
| **TGT**                | Ticket Granting Ticket — «главный» билет, подтверждает личность  |
| **Service Ticket (ST)** | Билет для доступа к конкретному сервису                         |
| **SPN**                | Service Principal Name — имя сервиса (`MSSQLSvc/db.example.com:1433`) |
| **Keytab**             | Файл с ключами сервиса (вместо пароля)                           |
| **krbtgt**             | Служебная учётная запись, её ключом шифруются все TGT            |

## **Как работает Kerberos**

```
   Клиент                    KDC (AS + TGS)                 Сервис
     |                            |                            |
  1. |--- AS-REQ (я alice) ------>|                            |
     |    + timestamp, зашифр.    |                            |
     |    ключом из пароля        |                            |
  2. |<-- AS-REP -----------------|                            |
     |    TGT (зашифр. ключом     |                            |
     |    krbtgt) + сеансовый ключ|                            |
     |                            |                            |
  3. |--- TGS-REQ --------------->|                            |
     |    TGT + "нужен HTTP/web"  |                            |
  4. |<-- TGS-REP ----------------|                            |
     |    Service Ticket (зашифр. |                            |
     |    ключом сервиса)         |                            |
     |                            |                            |
  5. |--- AP-REQ (Service Ticket + Authenticator) ------------>|
  6. |<-- AP-REP (опционально, взаимная аутентификация) -------|
```

### **Подробно по шагам**

| Шаг | Сообщение    | Описание                                                                   |
| --- | ------------ | -------------------------------------------------------------------------- |
| 1   | **AS-REQ**   | Клиент запрашивает TGT. Pre-authentication: метка времени, зашифрованная ключом из пароля |
| 2   | **AS-REP**   | KDC выдаёт TGT (клиент не может его расшифровать) и сеансовый ключ         |
| 3   | **TGS-REQ**  | Клиент предъявляет TGT и запрашивает билет на нужный SPN                   |
| 4   | **TGS-REP**  | KDC выдаёт Service Ticket, зашифрованный ключом сервиса                    |
| 5   | **AP-REQ**   | Клиент передаёт билет сервису. Сервис расшифровывает его своим ключом, KDC не участвует |
| 6   | **AP-REP**   | Сервис подтверждает свою подлинность клиенту                               |

### **Время жизни билетов (по умолчанию в AD)**

| Параметр                    | Значение   |
| --------------------------- | ---------- |
| Время жизни TGT             | 10 часов   |
| Максимальное продление      | 7 дней     |
| Время жизни Service Ticket  | 10 часов (600 минут) |
| Допустимое расхождение часов | 5 минут   |

## **Типы шифрования**

| Тип                        | Статус                                     |
| -------------------------- | ------------------------------------------ |
| **AES256-CTS-HMAC-SHA1-96** | Рекомендуется                             |
| **AES128-CTS-HMAC-SHA1-96** | Допустимо                                 |
| **AES256-CTS-HMAC-SHA384-192** | Новый (RFC 8009)                       |
| **RC4-HMAC**               | Устарел, уязвим, отключается в Windows     |
| **DES**                    | Запрещён                                   |

## **Делегирование (Active Directory)**

| Тип                              | Описание                                                 |
| -------------------------------- | -------------------------------------------------------- |
| **Unconstrained**                | Сервис получает TGT пользователя и может ходить куда угодно от его имени — опасно |
| **Constrained (S4U2Proxy)**      | Сервис может обращаться только к указанным SPN           |
| **Resource-Based Constrained (RBCD)** | Ресурс сам решает, кому разрешено делегирование     |
| **Protocol Transition (S4U2Self)** | Получение билета для пользователя без его пароля       |

## **Коды ошибок Kerberos**

| Код  | Название                       | Описание                                     |
| ---- | ------------------------------ | -------------------------------------------- |
| 6    | KDC_ERR_C_PRINCIPAL_UNKNOWN    | Пользователь не найден                       |
| 7    | KDC_ERR_S_PRINCIPAL_UNKNOWN    | SPN не найден                                |
| 12   | KDC_ERR_POLICY                 | Нарушение политики (время входа и т.д.)      |
| 14   | KDC_ERR_ETYPE_NOSUPP           | Тип шифрования не поддерживается             |
| 18   | KDC_ERR_CLIENT_REVOKED         | Учётная запись отключена или заблокирована   |
| 23   | KDC_ERR_KEY_EXPIRED            | Срок действия пароля истёк                   |
| 24   | KDC_ERR_PREAUTH_FAILED         | Неверный пароль                              |
| 25   | KDC_ERR_PREAUTH_REQUIRED       | Требуется предаутентификация (нормальный ответ) |
| 32   | KRB_AP_ERR_TKT_EXPIRED         | Билет истёк                                  |
| 37   | KRB_AP_ERR_SKEW                | Расхождение времени слишком велико           |
| 41   | KRB_AP_ERR_MODIFIED            | Не удалось расшифровать билет (неверный ключ/SPN) |

## **Примеры использования**

### **Linux (MIT Kerberos)**

```bash
# /etc/krb5.conf
[libdefaults]
    default_realm = EXAMPLE.COM
    dns_lookup_kdc = true

[realms]
    EXAMPLE.COM = {
        kdc = dc1.example.com
        admin_server = dc1.example.com
    }
```

```bash
kinit alice@EXAMPLE.COM          # получить TGT
klist                            # список билетов
kvno HTTP/web.example.com        # получить сервисный билет
kdestroy                         # удалить билеты
kinit -kt /etc/krb5.keytab HTTP/web.example.com   # вход по keytab
klist -kte /etc/krb5.keytab      # содержимое keytab
```

### **Windows**

```powershell
klist                  # текущие билеты
klist tgt              # информация о TGT
klist purge            # удалить билеты
setspn -L svc_sql      # SPN учётной записи
setspn -S HTTP/web.example.com svc_web   # добавить SPN
```

### **SSH с Kerberos (GSSAPI)**

```
# ~/.ssh/config
Host *.example.com
    GSSAPIAuthentication yes
    GSSAPIDelegateCredentials no
```

### **curl с Kerberos (SPNEGO)**

```bash
kinit alice
curl --negotiate -u : https://intranet.example.com/
```

### **Wireshark**

```
kerberos
kerberos.msg_type == 10    # AS-REQ
kerberos.error_code == 24  # неверный пароль
```

## **Атаки на Kerberos**

| Атака                   | Описание                                                          |
| ----------------------- | ----------------------------------------------------------------- |
| **Kerberoasting**       | Запрос сервисных билетов и офлайн-подбор паролей сервисных учёток |
| **AS-REP Roasting**     | Учётки без предаутентификации — офлайн-подбор пароля по AS-REP    |
| **Pass-the-Ticket**     | Кража билета из памяти и повторное использование                  |
| **Overpass-the-Hash**   | Получение TGT по NTLM-хэшу                                        |
| **Golden Ticket**       | Подделка TGT с помощью хэша krbtgt — полный контроль над доменом  |
| **Silver Ticket**       | Подделка сервисного билета с помощью ключа сервиса                |
| **Diamond/Sapphire Ticket** | Модификация легитимного TGT, сложнее обнаружить              |
| **Unconstrained Delegation abuse** | Кража TGT с серверов с неограниченным делегированием   |

### **Защита**

- Длинные случайные пароли для сервисных учёток, лучше **gMSA**
- Отключить RC4, использовать только AES
- Требовать предаутентификацию для всех учёток
- Регулярно менять пароль **krbtgt** (дважды при компрометации)
- Отказаться от неограниченного делегирования
- Группа **Protected Users** для привилегированных учёток
- Мониторинг событий 4768, 4769, 4771 (аномальные запросы билетов)

## **Сравнение Kerberos и NTLM**

| Характеристика        | Kerberos                     | NTLM                          |
| --------------------- | ---------------------------- | ----------------------------- |
| **Модель**            | Билеты, третья сторона (KDC) | Challenge-Response            |
| **Взаимная аутентификация** | Да                     | Нет                           |
| **Делегирование**     | Да                           | Нет                           |
| **Нагрузка на DC**    | Только при получении билета  | При каждой аутентификации     |
| **Криптография**      | AES                          | MD4/HMAC-MD5                  |
| **Требует DNS и времени** | Да                       | Нет                           |
| **Статус в Windows**  | Основной                     | Устаревает, отключается       |
