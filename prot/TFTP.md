**TFTP** (Trivial File Transfer Protocol) — упрощённый протокол передачи файлов поверх UDP. В нём нет аутентификации, просмотра каталогов и шифрования — только чтение и запись файла. Благодаря простоте TFTP помещается в ПЗУ сетевых карт и загрузчиков, поэтому используется для сетевой загрузки (PXE), обновления прошивок и сохранения конфигураций сетевого оборудования.

## **Основные характеристики**

| Параметр                    | Описание                                                                 |
| --------------------------- | ------------------------------------------------------------------------ |
| **Уровень OSI**             | Прикладной (Application Layer)                                           |
| **Транспорт**               | UDP                                                                      |
| **Порт**                    | 69 (только для первого запроса, далее — случайные порты)                 |
| **Стандарт**                | RFC 1350; опции — RFC 2347–2349, RFC 7440                                |
| **Аутентификация**          | Нет                                                                      |
| **Шифрование**              | Нет                                                                      |
| **Размер блока**            | 512 байт по умолчанию (до 65464 с опцией blksize)                        |
| **Надёжность**              | Stop-and-wait: каждый блок подтверждается                                |

## **Типы пакетов (Opcode)**

| Opcode | Пакет                | Описание                                     |
| ------ | -------------------- | -------------------------------------------- |
| 1      | RRQ (Read Request)   | Запрос на чтение (скачивание) файла          |
| 2      | WRQ (Write Request)  | Запрос на запись (загрузку) файла            |
| 3      | DATA                 | Блок данных                                  |
| 4      | ACK                  | Подтверждение блока                          |
| 5      | ERROR                | Ошибка                                       |
| 6      | OACK                 | Подтверждение опций (RFC 2347)               |

## **Структура пакетов**

### **RRQ / WRQ**

```
| Opcode (2) | Filename (строка) | 0 | Mode (строка) | 0 | [Опции...] |
```

### **DATA**

```
| Opcode=3 (2) | Block # (2) | Data (0–512 байт) |
```

### **ACK**

```
| Opcode=4 (2) | Block # (2) |
```

### **ERROR**

```
| Opcode=5 (2) | ErrorCode (2) | ErrMsg (строка) | 0 |
```

## **Режимы передачи (Mode)**

| Режим        | Описание                                             |
| ------------ | ---------------------------------------------------- |
| **netascii** | Текст, преобразование концов строк в CR LF           |
| **octet**    | Двоичный режим, файл без изменений (используется почти всегда) |
| **mail**     | Устарел                                              |

## **Процесс передачи**

### **Скачивание файла (RRQ)**

```
Клиент (порт 50000)                          Сервер (порт 69)
     |                                              |
     |--- RRQ "boot.img", octet ------------------>|  на порт 69
     |                                              |
     |<-- DATA блок 1 (512 байт) ------------------| с нового порта 60001
     |--- ACK блок 1 ----------------------------->|
     |<-- DATA блок 2 (512 байт) ------------------|
     |--- ACK блок 2 ----------------------------->|
     |              ...                             |
     |<-- DATA блок N (< 512 байт) ----------------|  последний блок
     |--- ACK блок N ----------------------------->|
     |           Передача завершена                 |
```

- Конец файла определяется блоком **меньше 512 байт** (если файл кратен 512 — отправляется пустой блок)
- Сервер отвечает с нового порта (TID), чтобы обслуживать несколько клиентов
- При потере пакета отправитель повторяет его по таймауту

### **Загрузка файла (WRQ)**

```
Клиент                                       Сервер
  |--- WRQ "config.txt", octet --------------->|
  |<-- ACK блок 0 -----------------------------|
  |--- DATA блок 1 --------------------------->|
  |<-- ACK блок 1 -----------------------------|
  ...
```

## **Коды ошибок**

| Код | Описание                                    |
| --- | ------------------------------------------- |
| 0   | Не определена (см. текст сообщения)         |
| 1   | Файл не найден                              |
| 2   | Нарушение доступа                           |
| 3   | Диск переполнен                             |
| 4   | Недопустимая операция TFTP                  |
| 5   | Неизвестный Transfer ID (порт)              |
| 6   | Файл уже существует                         |
| 7   | Нет такого пользователя                     |
| 8   | Отказ в согласовании опций (RFC 2347)       |

## **Расширения (опции)**

| Опция          | RFC      | Описание                                              |
| -------------- | -------- | ----------------------------------------------------- |
| **blksize**    | RFC 2348 | Размер блока (обычно 1428 или 1468 для Ethernet)      |
| **timeout**    | RFC 2349 | Таймаут повторной отправки                            |
| **tsize**      | RFC 2349 | Размер файла (клиент узнаёт заранее)                  |
| **windowsize** | RFC 7440 | Несколько блоков без ожидания ACK — заметно быстрее   |

Без опций на 1 ГБ файле в сети с RTT 1 мс нужно ~2 млн подтверждений — TFTP медленный.

## **Применение TFTP**

1. **PXE-загрузка** — DHCP сообщает адрес TFTP-сервера (опции 66, 67), клиент скачивает загрузчик
2. **Прошивка оборудования** — роутеры, коммутаторы, IP-телефоны, точки доступа
3. **Резервное копирование конфигураций** — Cisco `copy running-config tftp:`
4. **Восстановление «кирпичей»** — режим аварийной прошивки многих роутеров
5. **IP-телефоны** — загрузка конфигурации при старте

## **Примеры использования**

### **Сервер на Linux (tftpd-hpa)**

```bash
apt install tftpd-hpa

# /etc/default/tftpd-hpa
TFTP_USERNAME="tftp"
TFTP_DIRECTORY="/srv/tftp"
TFTP_ADDRESS=":69"
TFTP_OPTIONS="--secure --create"

systemctl restart tftpd-hpa
```

### **Сервер dnsmasq (вместе с DHCP для PXE)**

```
enable-tftp
tftp-root=/srv/tftp
dhcp-boot=pxelinux.0
```

### **Клиент**

```bash
# Linux (tftp-hpa)
tftp 192.168.1.10 -c get boot.img
tftp 192.168.1.10 -c put config.txt

# curl
curl -o boot.img tftp://192.168.1.10/boot.img

# Windows (компонент "TFTP Client")
tftp -i 192.168.1.10 GET boot.img
tftp -i 192.168.1.10 PUT config.txt
```

### **Cisco IOS**

```
copy running-config tftp://192.168.1.10/router1.cfg
copy tftp://192.168.1.10/ios.bin flash:
```

### **Wireshark**

```
tftp
udp.port == 69
```

## **Безопасность TFTP**

### **Проблемы**

1. **Нет аутентификации** — любой в сети может скачать или перезаписать файл
2. **Нет шифрования** — конфигурации с паролями передаются открыто
3. **Утечка конфигураций** — злоумышленники ищут в интернете открытые TFTP-серверы
4. **Перебор имён файлов** — имена конфигураций часто предсказуемы
5. **Отражённые DDoS** — TFTP использовался для amplification-атак

### **Защита**

- Не выставлять TFTP в интернет, ограничить доступ ACL/файрволом
- Режим `--secure` (chroot в каталог), запрет на запись (`--create` только при необходимости)
- Отдельная управляющая сеть / VLAN
- Удалять файлы конфигураций после использования
- Для передачи конфигураций использовать SCP/SFTP, для загрузки — HTTP(S) (iPXE)

## **Сравнение TFTP и FTP**

| Характеристика       | TFTP                     | FTP                               |
| -------------------- | ------------------------ | --------------------------------- |
| **Транспорт**        | UDP 69                   | TCP 21 (+ канал данных)           |
| **Аутентификация**   | Нет                      | Логин и пароль                    |
| **Просмотр каталогов** | Нет                    | Да                                |
| **Команды**          | Только чтение/запись     | Десятки команд                    |
| **Сложность**        | Очень простой            | Сложный                           |
| **Применение**       | PXE, прошивки            | Обмен файлами                     |
