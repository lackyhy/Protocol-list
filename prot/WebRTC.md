**WebRTC** (Web Real-Time Communication) — набор технологий и протоколов для передачи аудио, видео и произвольных данных напрямую между браузерами и приложениями, без плагинов. На WebRTC работают видеозвонки в браузере, конференции, облачный гейминг и P2P-передача файлов. WebRTC — это не один протокол, а «зонтик» над ICE, STUN, TURN, DTLS, SRTP и SCTP.

## **Основные характеристики**

| Параметр                    | Описание                                                                 |
| --------------------------- | ------------------------------------------------------------------------ |
| **Уровень OSI**             | Прикладной (набор протоколов)                                           |
| **Транспорт**               | UDP (предпочтительно), TCP/TLS как запасной                             |
| **Стандарты**               | W3C (WebRTC API), IETF (RTCWEB): RFC 8825–8835 и др.                     |
| **Медиа**                   | [SRTP](SRTP-RTCP.md) (шифрованный RTP)                                   |
| **Данные**                  | SCTP поверх DTLS (DataChannel)                                           |
| **Обход NAT**               | [ICE](STUN-TURN-ICE.md) (STUN + TURN)                                    |
| **Шифрование**              | Обязательно: DTLS-SRTP                                                    |
| **Сигнализация**            | Не стандартизирована (разработчик выбирает сам)                          |

## **Из чего состоит WebRTC**

| Компонент        | Назначение                                                      |
| ---------------- | --------------------------------------------------------------- |
| **ICE**          | Поиск рабочего пути между участниками через NAT                 |
| **STUN**         | Узнать свой внешний адрес                                       |
| **TURN**         | Ретрансляция, если прямое соединение невозможно                |
| **DTLS**         | Согласование ключей и шифрование                               |
| **SRTP**         | Шифрование и передача аудио/видео                              |
| **SCTP**         | Передача произвольных данных (DataChannel)                      |
| **SDP**          | Описание сессии (кодеки, адреса, параметры)                     |

## **Сигнализация (Signaling)**

WebRTC **не определяет**, как участники обмениваются начальной информацией (кто с кем хочет связаться, их SDP и ICE-кандидаты). Сигнализацию разработчик строит сам — обычно через WebSocket, HTTP или готовые решения (SIP over WebSocket, XMPP, Matrix).

```
Браузер A            Сервер сигнализации (WebSocket)            Браузер B
   |--- Offer (SDP) --------->|--------------------------------->|
   |                          |<-- Answer (SDP) -----------------|
   |<-- Answer (SDP) ---------|                                  |
   |--- ICE candidate ------->|--------------------------------->|
   |<-- ICE candidate --------|<-- ICE candidate ----------------|
   |                                                             |
   |======== прямое P2P-соединение (ICE + DTLS-SRTP) ===========>|
```

## **Этапы установления соединения**

```
1. getUserMedia() — доступ к камере и микрофону
2. createOffer() — браузер A формирует SDP-предложение
3. Обмен SDP через сигнализацию (offer/answer)
4. Сбор ICE-кандидатов (host, srflx через STUN, relay через TURN)
5. Обмен кандидатами, проверка пар (ICE connectivity checks)
6. DTLS handshake — согласование ключей
7. Передача медиа (SRTP) и данных (SCTP/DataChannel)
```

## **SDP — Session Description Protocol**

SDP (RFC 8866) описывает параметры сессии в текстовом виде:

```
v=0
o=- 46117 2 IN IP4 127.0.0.1
s=-
t=0 0
a=group:BUNDLE audio video
m=audio 9 UDP/TLS/RTP/SAVPF 111 103
a=rtpmap:111 opus/48000/2
a=fingerprint:sha-256 AB:CD:...          ← отпечаток DTLS-сертификата
a=ice-ufrag:4ZcD
a=ice-pwd:by...
a=setup:actpass
m=video 9 UDP/TLS/RTP/SAVPF 96 97
a=rtpmap:96 VP8/90000
```

## **Основные API (JavaScript)**

| API                      | Назначение                                     |
| ------------------------ | ---------------------------------------------- |
| `getUserMedia()`         | Доступ к камере и микрофону                     |
| `getDisplayMedia()`      | Захват экрана                                   |
| `RTCPeerConnection`      | Соединение, медиа, ICE                          |
| `RTCDataChannel`         | Передача произвольных данных                     |
| `createOffer/createAnswer` | Формирование SDP                              |
| `addIceCandidate`        | Добавление ICE-кандидата                        |

## **Кодеки**

| Тип      | Кодеки                                              |
| -------- | --------------------------------------------------- |
| **Аудио** | Opus (основной), G.711 (PCMU/PCMA)                 |
| **Видео** | VP8, VP9, H.264, AV1 (новые браузеры)              |

## **DataChannel**

`RTCDataChannel` передаёт произвольные данные поверх SCTP/DTLS. Можно выбирать режим доставки:

| Режим            | Описание                                      | Аналог  |
| ---------------- | --------------------------------------------- | ------- |
| **Reliable, ordered** | Гарантированная доставка по порядку      | TCP     |
| **Unreliable, unordered** | Без гарантий (maxRetransmits=0)       | UDP     |
| **Partially reliable** | Ограниченное число повторов или время     | —       |

Применение: чат, передача файлов, синхронизация состояния игр, телеметрия.

## **Архитектуры конференций**

| Архитектура | Описание                                                        | Масштаб     |
| ----------- | --------------------------------------------------------------- | ----------- |
| **Mesh (P2P)** | Каждый соединяется с каждым напрямую                          | 2–4 участника |
| **SFU** (Selective Forwarding Unit) | Сервер пересылает потоки, не декодируя | Десятки участников |
| **MCU** (Multipoint Control Unit) | Сервер микширует все потоки в один      | Много, но дорого по CPU |

Популярные SFU: mediasoup, Janus, Jitsi Videobridge, LiveKit, Pion.

## **Примеры использования**

### **Минимальный DataChannel (один браузер, для теста)**

```javascript
const pc1 = new RTCPeerConnection();
const pc2 = new RTCPeerConnection();

const dc = pc1.createDataChannel("chat");
dc.onopen = () => dc.send("Привет!");
pc2.ondatachannel = (e) => { e.channel.onmessage = (m) => console.log(m.data); };

pc1.onicecandidate = (e) => e.candidate && pc2.addIceCandidate(e.candidate);
pc2.onicecandidate = (e) => e.candidate && pc1.addIceCandidate(e.candidate);

const offer = await pc1.createOffer();
await pc1.setLocalDescription(offer);
await pc2.setRemoteDescription(offer);
const answer = await pc2.createAnswer();
await pc2.setLocalDescription(answer);
await pc1.setRemoteDescription(answer);
```

### **Конфигурация ICE-серверов**

```javascript
const pc = new RTCPeerConnection({
  iceServers: [
    { urls: "stun:stun.l.google.com:19302" },
    { urls: "turn:turn.example.com:3478", username: "user", credential: "pass" },
    { urls: "turns:turn.example.com:5349", username: "user", credential: "pass" }
  ]
});
```

## **Безопасность WebRTC**

### **Встроенная защита**

- **Шифрование обязательно** — медиа всегда через DTLS-SRTP, отключить нельзя
- **Отпечаток сертификата в SDP** — защита от MITM (при условии защищённой сигнализации)
- **Запрос разрешения** на камеру/микрофон/экран у пользователя
- **Согласие (consent freshness)** — периодическая проверка, что получатель всё ещё согласен принимать трафик

### **Риски**

| Риск                           | Описание                                                    |
| ------------------------------ | ----------------------------------------------------------- |
| **Утечка локального IP**       | ICE раскрывает приватные и публичные адреса пользователя (деанонимизация даже за VPN) |
| **Незащищённая сигнализация**  | Если сигнализация без TLS, возможен MITM-подмена отпечатка  |
| **TURN как открытый релей**    | Неправильно настроенный TURN ретранслирует чужой трафик     |
| **Исчерпание ресурсов**        | Множество соединений нагружают SFU/TURN                     |

### **Защита**

- Сигнализация только по WSS/HTTPS
- TURN с аутентификацией и временными учётными данными (REST API, RFC 7635)
- Для анонимности — политики браузера, ограничивающие раскрытие локальных IP (`force-relay`)
- Проверка `a=fingerprint` через доверенный канал

## **Сравнение WebRTC и других технологий RTC**

| Характеристика       | WebRTC                   | SIP + RTP                 | RTMP                      |
| -------------------- | ------------------------ | ------------------------- | ------------------------- |
| **Где работает**     | Браузер, мобильные, нативные | Телефония, софтфоны   | Стриминг (устаревает)     |
| **Плагины**          | Не нужны                 | Отдельное ПО              | Flash (мёртв)             |
| **Шифрование**       | Обязательно              | Опционально (SRTP)        | Опционально (RTMPS)       |
| **Задержка**         | Очень низкая (< 500 мс)  | Низкая                    | Средняя (секунды)         |
| **P2P**              | Да                       | Обычно через сервер       | Нет (клиент-сервер)       |
| **Передача данных**  | DataChannel              | Нет                       | Нет                       |
